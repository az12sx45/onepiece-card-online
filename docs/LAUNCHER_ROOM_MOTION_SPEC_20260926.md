# 房間角色重製規格（1.1.13 候選）

日期：2026-09-26；最後更新：2026-09-27。狀態：十名角色、四方向的 source 圖集與工具 gate 已完成；仍待完整真實房間動態 review 與部署讀回。舊版 1.1.12 的程式測試通過不代表步態合格。

## 已確認的問題

- 舊版每次只交換兩張張腿圖，沒有腳通過骨盆下方的過程。
- 個別影格以各自的外框放大，造成頭與軀幹的尺度變動。
- 只有左右鏡像，縱向路徑沒有對應的前／後圖；鏡像還會交換刀鞘、耳環、刺青和遮眼側。
- 對話只有兩句，整張人物的 CSS 搖晃不能代替表情與動作。

## 製作順序與拒收條件

先完成魯夫一個方向的相反接觸姿勢，再補通過／承重影格；整段循環合格後才擴四方向和其他角色。一次生出八張相似張腿圖不算步行循環。首兩批 east 候選因第二半循環未可靠交換近遠腿與手臂，已拒收。

逐張試做已取得兩個相反接觸姿勢，但還有影格間五官／比例與支撐腳跳動；因此改用 GPT 完整分層部件、連續骨架及烘焙圖集。分層只拆開既有原作角色，沒有用程式補畫角色。原畫必須提供被遮住的肩、髖、膝與踝；內部接縫可裁到重疊區，不可用色塊遮蓋缺圖。

固定 12 格部件契約：第一列四個同方向頭部（安靜、開心、不悅、驚訝）；第二列軀幹含骨盆、近臂、遠臂、近腿；第三列遠腿、近腳、遠腳、配件。腿到踝不含腳，完整長褲／袖口保留在連續網格；north/south 的近／遠欄位依序指定解剖右／左，east 為右／左、west 為左／右。頭部不同表情不可交換耳環、傷疤或遮眼側；背面頭部不畫臉。

所有步幅與速度必須以房間前排 96 px 畫布換算，不將 256 px 放大檢查頁的數字直接作為遊戲速度。首輪短步候選約 24–30 px／循環、28–32 px／秒，實際以腳底世界位置核對；固定下移骨盆造成的全程蹲膝已列為拒收項。

每名角色都須檢查服裝、臉、解剖側配件、交替支撐、頭身尺度、32→1 接縫；接地與視覺連續性不可由 alpha、張數、關節公式或 SHA 檢查代替。

2026-09-27 投影修正：純 Y 的北南圖集在梯形地板兩侧實測約 3.9px 橫向支撐腳漂移，因此加入五組腿部投影。烘焙時維持頭、軀幹、手臂不變，只讓原畫腿／腳部件配合地面方向；不切玩家畫面上的身體、不對整張人形做斜切。魯夫候選在左右外側的 renderer 腳踝座標漂移約 X 0.23–0.26px / Y 0.39–0.41px，在兩組斜率之間的列約 X 0.96–0.99px / Y 0.39–0.41px。這些數值來自實際 root／frame 與烘焙關節座標，並非影像追蹤或十角色視覺验收。

封裝時將保留的 256px cell 烘焙 PNG 以 Lanczos 統一縮成 128px cell，再無損編碼 WebP；播放器核對發布尺寸，供約 96px 房間角色使用，解碼並行上限為兩張。manifest 同時記錄原始烘焙、縮圖方式、前後格內外框與 SHA；此縮圖降低安裝檔大小及解碼記憶體，不改方向、舞台步幅、比例或接地根。個人詳情另使用原始 256px 南向 idle 裁圖，避免舊服裝混入。產物保存每張 GPT 原稿、實際 prompt、原始與正規化 receipt、每個部件來源、spec 與 renderer hash。多來源修正（例如僅更換軀幹）需逐張保存原稿與提示詞。最終視覺 review 綁定實際發布 atlas SHA，不能沿用舊尺寸的驗收。

## 驗證

目前已執行：80 張發布 atlas、10 張新版詳情圖的來源／spec／renderer／原始烘焙／WebP SHA 驗證；控制器 16 項、使用真台詞與模擬動畫的瀏覽器整合 72 項、可攜 pipeline 隔離檢查 8 項，以及 source package QA 通過。Root 已目視十張發布像素 contact sheets，涵蓋四向步態每四幀取樣與八姿勢；這是時間取樣，不能代替連續播放。家具手勢仍依實際接合結果定向修正，修正後須重新綁定成品 SHA 與 review。review plan 先保留 pending，完整動態證據及明確確認前不升級狀態；正式封裝／部署驗收另行記錄。

1. 四方向正常與半速循環；接觸、承重、通過、前擺可辨識。
2. 真實房間中走水平、縱向、轉角、停下、面向夥伴、對話、到家具工作。
3. 以疊影比對支撐腳世界位置，校準速度／步幅；房間畫面支撐段漂移目標 2 px 以內。
4. 對話跑完整場景，確認說話順序、聽者表情、點選與工作中斷、冷卻及重複抑制。
5. 桌機／窄螢幕、多人互擋、家具遮擋、素材解碼失敗。
6. 打包後 opui 素材讀取與完整性；部署後簽章、公開 manifest、安裝檔 bytes／SHA 讀回。未執行的項目明確列待驗。
