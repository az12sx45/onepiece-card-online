# Game Rules

## Card Finish V1 規則邊界（2026-09-06，已發布）

正式版 `986430ca` 已通過發布後真實 hand／drawn、自然青雉禁選、目標選擇與對手同步；原 inline 遊戲程式與 14d08902 完全相同。本次只有四接點與獨立視覺層，沒有變更 Card／Board 規則、帳號、存檔或 Socket 事件。完整驗收限制見 `docs/CARD_FINISH_V1_RELEASE.md`。

### 發布前規則邊界紀錄（歷史）

- Card Finish V1 只讀取現有卡圖、按鈕 disabled／冰凍狀態及選牌容器來顯示 plain／foil 外觀；不接管原點擊、不改 `PLAY_CARD` payload、目標選擇、出牌、禁選、強化動畫時序、勝負或多人事件。
- 新版單元 `4,437` assertions、瀏覽器 `172` 項且 `0` page errors 均通過。正式雙帳號候選對局亦已確認手牌與抽牌各一次只送一個權威 `PLAY_CARD` 且另一端一致；手動騙人布 disabled 選項與 runner 自然遇到的青雉冰凍手牌，實體點擊都沒有送出事件或改變權威 state。
- 連續 runner 的 hand／drawn／peer sync／finish hooks／自然禁選與禁選攔截均為 true，預發布 Service Worker／資源 QA 亦為 `93` 項 PASS。娜美兩牌禁選仍只由 fixture 覆蓋，公開 live／postdeploy 尚待上線後執行，所以不能把它另稱為已自然遇到或已部署驗證。
- 本候選不修改 Card／Board 規則、server、DB、帳號、存檔、同步、localStorage key、Socket.IO event 或 `BOARD_GAME_STATE`，且尚未 commit、push 或部署。詳見 `docs/CARD_FINISH_V1_RELEASE.md`；前次 GPL 候選只作未上線歷史紀錄，見 `docs/CARD_HOLO_V458_RELEASE_REPORT.md`。

本文件整理目前程式碼中大富翁 / Board 遊戲已存在的規則來源。這不是新設計稿；若與程式碼衝突，以目前程式碼為準，並應先更新程式或文件之一來消除衝突。

## 多人戰鬥續戰規則（V458）

- 一輪中雙方各完成行動後，戰鬥可以暫停並依原玩家順序交棒；輪回該參戰者並續戰時必須開始新輪，上一輪的玩家／敵方已行動旗標、骰值及行動摘要全部清空。
- 每個新輪都重新依本輪行動優先度與有效速度決定先攻，上一輪的 `firstActor`／`secondActor` 不得沿用。同一輪因刷新而接回未完成結算時則仍保留既定先攻，避免重算造成順序改變。
- 共鬥戰的參戰者 runtime 必須在新輪開場效果處理後同步更新；玩家選招時不可再被舊 runtime 覆蓋成「已行動」而略過擲骰。這項修正沿用既有完整 `BOARD_GAME_STATE` 與存檔結構。
- 四個主戰鬥指令的功能與順序不變；顯示上採左右對稱內縮及等距排列，低高度橫向畫面會額外縮向中央，不能壓到裝飾邊框。

## 專屬滑鼠游標規則（V457）

- 精準滑鼠／觸控筆環境中，Board 羽毛筆固定為筆尖朝左下，游標熱點位於左下筆尖；地圖與其他可拖曳區域在待拖曳時顯示羽筆互動態，按住拖曳時顯示羽筆按下態，不改用系統抓取手標。
- 文字輸入仍使用文字游標，卡牌海報仍可顯示放大游標，Board 準星與等待狀態仍依功能顯示；touch-only 裝置不套用自訂游標或墨圈。
- Card 與 Board 的網頁根層卷軸外觀隱藏，但頁面本身仍能用滾輪、鍵盤與觸控捲動；聊天室、modal、角色或商品清單等內層卷軸照常顯示與操作。
- 本版只改客戶端操作外觀，不改拖曳座標、回合、戰鬥、角色、道具、帳號、存檔、同步或 Socket.IO event。

## 專屬滑鼠游標規則（V456）

- 精準滑鼠／觸控筆環境中，卡牌遊戲目前使用無手臂的巴奇白手套：一般與可點擊態張開，主要按鍵按下時捏合。Board 目前使用娜美白羽毛筆，游標熱點位於筆尖。
- Card 點擊保留短紅金回饋；Board 點擊以不規則黑墨圈及小墨點標示選取位置。回饋節點不接收 pointer event，動畫結束後必須自行移除，不能遮擋原按鈕。
- 觸控裝置不啟用這套游標或墨圈；文字輸入、disabled、拖曳、準星與海報放大仍依原頁面語意顯示。這是純客戶端視覺，不改任何遊戲規則、存檔或多人同步。

## 專屬滑鼠游標規則（V455）

- 精準滑鼠／觸控筆環境中，卡牌遊戲使用巴奇白手套三態游標，Board 使用娜美海圖筆三態游標；可點擊目標亮起、主要按鍵按下時顯示下壓態與短暫光圈。
- 觸控裝置不建立自訂游標或點擊光圈，現有手勢與滑動不受影響。文字輸入仍使用系統文字游標；禁用控制不會顯示可點擊態；既有拖曳、準星與海報放大游標在未按下時保留。
- 這是純客戶端外觀／操作回饋，不改回合、攻擊、卡牌、角色、道具、帳號、存檔、同步、`BOARD_GAME_STATE` 或任何 Socket.IO event。

- `launcher-release-v1.json` 只提供啟動器版本資訊；檢查更新、顯示最新版或未來下載新版均不得改動任何遊戲角色、道具、回合、房間、存檔、Socket.IO event、localStorage key 或 `BOARD_GAME_STATE`。
- 現行 `1.1.2` manifest 沒有 artifact，不能觸發下載或安裝；未驗證的新安裝檔不得宣告為可用更新。

## 卡牌進場遮罩顯示邊界（V434）

- 帶 `.hidden` 的通用對話框、硬幣／出牌遮罩與抽牌／選牌提示，在既有遊戲流程明確開啟前必須保持 `display:none`，不得顯示空暗幕、錯誤階段提示或攔截玩家點擊；移除 `.hidden` 後仍依原本條件、內容與動畫顯示。
- V434 只修正顯示層 CSS cascade，不改牌效、抽牌、回合順序、勝敗、Socket.IO event、localStorage 或持久狀態。

## 卡牌／桌面運行效能邊界（V433）

- V433 是渲染與本機素材供應修正，不改卡牌或 Board 的角色、牌效、道具、戰鬥、回合、地圖、獎勵及勝敗條件，也不改任何既有 ID、Socket.IO event、localStorage key、持久存檔 schema 或 `BOARD_GAME_STATE`。
- 卡牌 `STATE` 與帶日誌的 `EMIT` 可以合併在同一 animation frame 顯示，但收到狀態、播放事件及決定操作權的邏輯仍立即執行；場地、棄牌、玩家或日誌 fingerprint 未變時只保留原 DOM，不代表忽略新遊戲狀態。
- 一次抽牌操作不論由影片 `ended`、點擊略過或 failsafe 完成，都只能送一個 `DRAW`。麻痺狀態同一 round／turn／draw／skipNext 組合只能自動送一次，離開條件後才解除防重；這是防止重複指令，不改麻痺原本跳過抽牌的效果。
- 桌面已安裝素材仍須先通過 manifest／receipt／size／SHA 驗證。運行時 path／token 記憶體索引、單檔不超過 8 MiB 與 192 MiB 總量 LRU、以及大型檔案串流只改讀取方式；長度錯誤仍觸發清除索引與修復檢查，不得把損壞素材視為有效。
- Card／Board 的 Electron partition 仍為非持久，`cache:false` 禁用 HTTP 磁碟快取，登入 localStorage 不可跨程序保存。一般關閉再開遊戲會保留本次啟動器程序內的非帳號設定與 Board 手動存檔，登出、被踢或切換素材位置才清除；選定 D 槽時，V8 code cache 與 Chromium session／GPU／network cache 也跟隨素材根目錄落在 D 槽。帳號密文狀態仍留在 userData，這不建立第二份帳號、房間或遊戲存檔。
- 效能診斷初期 C 槽曾為 `0 bytes` 可用，最後重測已恢復約 30.7 GiB；V433 沒有授權或執行使用者檔案刪除，且仍把可移動的遊戲快取放到選定的 D 槽來降低將來風險。

## 桌面啟動器與遊戲安裝邊界（V431～V432）

- 桌面啟動器只改變媒體的取得位置，不改卡牌或 Board 的角色、道具、戰鬥、回合、地圖、存檔 schema、localStorage key、Socket.IO event 或 `BOARD_GAME_STATE`。網頁與桌面玩家仍能進同一正式房間。
- 玩家必須先通過正式帳號驗證才能安裝或啟動；renderer 傳來的 game id 仍由 main process 白名單複查。只允許 `card`、`board`，《霸海戰棋》在 catalog、UI 與 IPC 三層都保持不可下載／不可啟動。
- 每款遊戲只有在 receipt 對應的不可變 manifest 存在、所有必要 blob 可用且狀態不是修復中時才能啟動。素材請求必須同時符合允許根目錄、已安裝 manifest、大小、SHA-256 與內容位址；失敗會把該遊戲標成需要修復並回退正式 HTTP，不可把損壞檔當成已安裝版本啟動。
- 更新採內容位址快取與原子切換：新版本全部下載、驗證及寫入 receipt 成功前，舊 receipt 始終是 last-known-good；取消、離線、伺服器暫時錯誤或新檔損壞都不得破壞舊版本。遠端 catalog 必須完成格式與 manifest 摘要驗證後才能保存，離線重啟不可用較舊 bundled catalog 將已裝新版降級。
- 下載可保留 `.part` 並用 HTTP Range 續傳；只對網路錯誤、408、429 與 5xx 做有限次退避重試，內容雜湊不符不盲目重試。下載前保留安全磁碟空間，改下載位置時不得有進行中的工作。
- 有效素材的完整 SHA 結果可用檔案 stat 指紋持久保存，重開後先走快速指紋比對，再由有限量背景稽核抽查；stat 改變、抽查失敗或執行時異常都要重算／修復。這只優化驗證，不降低 SHA-256 作為真實內容權威的規則。
- 桌面遊戲採非持久 Electron session。開啟前清除 Service Worker／CacheStorage 並阻擋正式根 `/sw.js`，避免同一批媒體被二次快取；登入 localStorage 只存於當次程序，登出／`SESSION_KICK` 會關閉視窗並清除。密碼不得寫入檔案、URL、localStorage 或錯誤訊息。
- 安裝器與啟動器不得內含 server、資料庫設定、帳密、私人存檔、`incoming`、備份或未發布西洋棋 runtime。Windows 圖示與安裝精靈插圖只是桌面包裝，不參與任何遊戲規則或同步狀態。
- manifest 必須描述正式站實際供應的 Git committed bytes；Windows 換行轉換不得成為下載 SHA 的來源。這是素材完整性規則，不改任何角色、戰鬥、回合或多人規則。

## Windows 桌面圖片快取邊界（Beta V430）

- 桌面版只改變正式 `/images/*` 的傳輸來源，不改圖片 URL、素材 id、遊戲規則、`gameState`、localStorage key、Socket.IO event 或 `BOARD_GAME_STATE`。網頁版與桌面版玩家可進同一房間。
- 本機圖片必須存在於受控 manifest、realpath 留在安裝圖片根目錄，且檔案大小與 SHA-256 完全符合；任一條件不符就保留原 HTTP 請求，不能用未驗證檔案取代正式素材或阻斷遊戲。
- Git 中只差大小寫、但 Windows 無法安全並存的 `ranks/r5`、`ranks/r6` 四個 URL 必須列在 manifest 排除清單並固定走正式 HTTP，不可任意合併成同一張本機圖片。
- 登入、好友、聊天室、房間、雲端存檔與多人同步必須繼續連正式伺服器；圖片快取不代表離線版。Beta 未快取音樂與影片，這兩類仍依現有網站規則載入。
- 安裝包不得包含 `battle_chess`、`incoming`、`private`、備份、資料庫設定、帳密或私人存檔。桌面 renderer 不開放 Node API，並拒絕外站導覽與新視窗。

## 多人斷線與重新連線規則（Board V429）

- Board 房間版本必須單調遞增。完整快照只能從 server 目前版本提交下一版；`baseVersion` 過期、跳號或重複的更新一律拒絕，不能覆蓋房間已保存的較新狀態。交易完成、交易關閉與戰鬥追趕也不得例外接受低版本快照。
- 同一普通遊戲房內，只要 `userId` 或 `clientId` 相同，就只保留最後加入的遊戲 socket 作為控制端。較舊分頁或斷線殘留 socket 被 fencing 後，只能停留在鎖定狀態，不能再送完整快照、遊戲事件或狀態請求。
- 裝置離線或尚未取得權威狀態時，該頁不得接受新的真人遊戲操作，也不得讓其控制的 CPU 繼續回合。斷線前已經開始的動畫／行動可以完成結算，但結果只能先保留在記憶體佇列，不能假裝 server 已收到。
- 每個客戶端同時只送一份完整快照；傳送期間的新變化只保留最後一份。重新連線後，server 若仍在客戶端已知版本便補送最新結果；server 若已有更新版本，客戶端必須捨棄舊佇列並套用 server 權威快照。
- `pendingState`、`inFlightState` 與連線旗標只屬頁面 runtime，不寫入手動存檔、campaign、localStorage 或 `gameState`。既有角色、道具、戰鬥、回合與 PK 規則不因這項同步防護改變。

## 正式桌遊選擇規則（V428）

- 正式站的卡牌入口與既有登入流程保留；卡牌主選單的隱藏骰子通往共用桌遊啟動器。
- 啟動器通過正式帳號驗證後，目前只有卡牌與《新世界航海錄》可進入。《霸海戰棋》盒面可見但不可操作，且不得載入其預覽影片或發布其 runtime。
- 本機開發時，只有 loopback 且 `/api/board-runtime` 明確回報帳號資料庫未啟用，才可恢復西洋棋本機連結；這個例外不能在正式站或 LAN 位址啟用。
- 這項入口整合不改任何戰鬥、回合、捕捉、角色、道具、campaign、`BOARD_GAME_STATE` 或 Socket.IO 同步規則。

## 三合一桌遊啟動入口邊界（V427）

- 開啟 `game_launcher_preview.html` 固定先停在系列主畫面；玩家點擊畫面或按任意非修飾鍵後，才能進入登入驗證。帳號成功前，三個桌遊連結必須維持 `inert` 與 `aria-hidden`，不可由鍵盤或滑鼠誤進。
- 正式來源只接受同源 `AUTH_LOGIN`／`AUTH_REGISTER`、`PROFILE_GET` 與 `PRESENCE_SET`；有效既有 secret 仍須在點擊後重新驗證。密碼不得寫入 localStorage、URL 或錯誤訊息，送出後清空；被 `SESSION_KICK` 時清除 secret 並回登入。
- 空白登入只准用於 loopback 且 `/api/board-runtime` 明確表示未連帳號資料庫的本機預覽；它會使用本機測試身分，不建立假 secret。非 loopback、資料庫已啟用、能力旗標逾時或未知時都不得啟用此捷徑。
- 驗證成功只解鎖原收藏室，不改三個遊戲的內部登入安全邊界、房間、回合、角色、道具、存檔、`BOARD_GAME_STATE` 或任何 Socket.IO event 名稱；三條入口 href 與 V415／V417 核准構圖維持不變。

## 共用好友與聊天室保留規則（V426）

- 「好友與聊天室」、浮動好友 Dock、聊天 Tray 與邀請層是預定和《偉大航道爭霸戰》共用的正式介面，本機預覽也必須保留，不屬於可移除的無效功能。
- 尚未接回正式帳號 secret 時，介面只顯示待接入狀態，不偽造好友、訊息或邀請；接回後沿用既有 `SOCIAL_*`、`DM_*` 與房間邀請事件。
- 本機首頁仍隱藏無內容的玩家資料；繼續航海只有實際取得可用 campaign 才顯示。

## 本機首頁入口顯示規則（V425；V426 恢復社交入口）

- local-preview 首頁只顯示可以完成動作的入口：「開始航海」固定存在；「繼續航海」須等伺服器回傳至少一份可用紀錄才顯示。
- 因本機預覽沒有登入 secret，「玩家資料」不顯示；好友與聊天室相關介面依 V426 保留並顯示待接入狀態。
- 這些限制只屬本機預覽顯示層；正式帳號模式仍依原規則提供四入口，不修改房間、campaign、存檔或同步資料。

## 本機登入預覽邊界（V424）

- 僅當網址主機為 `127.0.0.1`、`localhost` 或 `::1`，且 `/api/board-runtime` 明確回報帳號資料庫關閉時，登入卡允許空白直接進入主畫面。
- 本機預覽只建立本機測試玩家資料，不保存密碼或登入 secret，也不把帳密送到正式站；Board 房間與遊戲同步仍使用目前本機 Socket。
- 正式網址、非 loopback 網址與已啟用資料庫的環境不得使用此捷徑，仍須通過原 `AUTH_LOGIN`／`PROFILE_GET`。此規則不新增存檔欄位、Socket.IO event 或 `BOARD_GAME_STATE` 內容。

- 不會在等待室一次預載所有遊戲原圖；V397 只預先下載固定的行動裝置進場素材，其他素材仍於實際需要時載入，以控制 Render 流量與解碼壓力。

## 登入裝置識別啟動順序（V395）

- 卡牌登入首頁在同步 script 階段先建立 `window.getDeviceId`，好友面板與 React 登入程式共用既有 `op_device_id`；這只是避免載入競速造成第一次好友驗證失敗，不改單裝置登入規則、帳號資料、房間或 Board 存檔。

## 登入首頁、好友與私人訊息（V394）

- Board 開始頁固定先顯示四個入口：開始航海、繼續航海、好友與聊天室、玩家資料。建立／加入房間與共有航海紀錄都在各自第二層頁面；只有 URL 明確帶 `view=lobby`／`view=modeSelect` 等既有參數時才直接進指定流程。
- 正式好友功能必須有卡牌登入帳號的 secret，並由 `SOCIAL_AUTH` 綁定目前 Socket；好友名單、收到／送出的邀請與在線狀態由 server／PostgreSQL 回傳。未登入不建立假好友，也不能傳私訊或房間邀請。
- 好友邀請以玩家名稱送出，對方必須確認後才成為雙向好友。確認、拒絕或刪除會同步更新雙方資料；`FRIENDS_DIRTY` 使在線客端重新取得清單。
- 私訊只允許傳給目前好友，單則最多 400 字。開啟聊天室先以 `DM_HISTORY` 取回最近紀錄；`DM_SEND` 成功後寫入資料庫，接收者以 `DM_NEW` 即時收到。好友面板的未讀與縮小提示只是 UI，不進 `BOARD_GAME_STATE` 或遊戲存檔。
- Board 等待室邀請沿用 `LOBBY_INVITE_SEND`／`LOBBY_INVITE_RESPOND` 並帶 `mode:"board"`。送出時必須是好友、接收者在線、邀請者本人位於該 Board 等待室且房間尚未開局；接受時 server 再驗證房間仍存在且仍在等待，之後才由既有 `BOARD_JOIN_ROOM` 真正加入。拒絕或暫停 5 分鐘不改 Board 回合／存檔。

## 多人快照、輕量演出與航海紀錄

- `BOARD_GAME_STATE` 仍是房間內唯一可改變玩家、地圖、回合、戰鬥、交易、切磋與 campaign 執行狀態的完整權威快照；加入、刷新與主動要求狀態時一律取回完整快照。
- `BOARD_GAME_EVENT` 只負責短暫 UI 與逐格船位，不寫入手動存檔、campaign 或 server 的房間快照。觀看端收到逐格船位時只移動 DOM 船圖，不改自己的 `gameState.players[*].location`；下一份完整快照會重新校正。
- 一般移動每格送一個輕量事件，連續移動最多每 4 格補一份完整檢查點；抵達島嶼、開啟事件／戰鬥／選擇、交易、切磋、交棒與結算仍依原流程送完整快照。斷線最差只從最近檢查點或重要狀態接回，不靠動畫事件恢復規則。
- 短暫 UI 事件含房間序號與到期時間。客端拒絕已過期或倒序事件；新事件會取代舊事件，到期後清除自己的 HUD、骰子或觀看彈窗。`boardUiEvent` 不再保存於完整快照，因此刷新不會重播舊畫面；交棒提示仍先播完指定延遲再套用後續快照。
- 漂流寶箱屬於短暫觀看演出，但必須依序同步「四個候選出現、操作方確認後洗牌、抽中種類與結果」三段。觀看方使用與操作方相同的正式寶箱圖、洗牌框及金色開箱結果框；卡片與按鈕只供觀看，不能代替當前玩家選箱。寶箱獎勵只由操作方結算，最後仍由完整快照校正。
- 最終之島重訪與「大熊的肉球航路」也屬短暫觀看演出。觀看方使用與操作方相同的航海情報框與 13 張 Boss 線索羅盤；操作方切換線索牌時只送含 `selectedBossKey` 的輕量事件，不額外送完整快照，觀看方同步顯示同一張，但卡片、左右箭頭與目的地確認皆為唯讀。未知的新觀看彈窗一律使用正式航海情報框後備，不得退回舊藍色 HUD；後備畫面不具任何結算權限。
- 航海紀錄只保留最新 500 筆。載入舊長存檔時，程式會先依完整舊紀錄補發已取得的既有外觀框狀態，再裁切顯示紀錄；玩家、角色、道具、任務與圖鑑等正式狀態不靠被裁掉的文字繼續運作。
- WebSocket 對 1 KiB 以上訊息啟用壓縮。這只改傳輸編碼，不改畫面時序、骰子結果或傷害；server 仍驗證完整快照及輕量事件的目前玩家／戰鬥／切磋／交易控制權。

## 二周目共有航海紀錄與個人／集合遊玩

- 開始頁以既有登入帳號 key `op_user_id` 作為 campaign 身分；帳號存在時，名稱與頭像直接由帳號資料帶入，不在 Board 開始頁另行修改。未登入狀態只使用本機測試資料，名稱／頭像選擇收在玩家資料選單內，不影響正式帳號紀錄。
- 「我的航海紀錄」只列出目前 user id 是固定成員的 campaign。卡片中的回合、位置、船員與狀態均為該帳號自己的最新正式紀錄；其他成員的代理 CPU 臨時成果不會混入。
- 一份共有航海紀錄的成員名單，在正常多人房首次於二周目解鎖後手動存檔時確立；正 user id 為原真人成員，負 user id 的 CPU 為原生 CPU。所有原真人在開始頁都能列出同一 campaign，但個人紀錄各自保存。
- 「個人遊玩」會建立獨立執行房：開啟者保持真人控制；其他原真人以自己上次正式個人紀錄載入，但標為代理 CPU；原生 CPU 從開啟者分流載入。不同玩家可同時各開一個分流，彼此的即時回合不互相鎖住。
- 個人遊玩從開始頁換到遊戲頁時，只有同一 user id 與 client id 可一次性接手剛建立的席位；載入成功後直接回到該分流原本的 `phase`／回合／位置，不重新進入「開始出航」。campaign 快照載入失敗時禁止建立或推送空白新局，只能返回開始頁重選。
- 個人分流存檔只更新呼叫存檔者的玩家紀錄與該玩家的分流快照。代理 CPU 替缺席者取得的角色、道具、貝里、位置、培養及其他成果不會更新缺席者紀錄；缺席者回來時一律用自己最後一次正式存檔。
- `postgameWorld.unlocked`、最終之島、研究所、蛋頭島與最終結局等共同解鎖採布林聯集：任何成員開啟後，全 campaign 後續載入都維持開啟；個人角色、背包、位置與資源不做聯集。
- 「集合遊玩」必須在各人完成當前戰鬥、移動、路線／事件、交易、共鬥、切磋與島嶼決定後存檔，再從開始頁進集合等待室。只有 campaign 成員可加入，固定名單不能增減原生 CPU；所有已加入真人都準備後才可開始。
- 集合局以發起者所選分流作底：當前輪數、行動順位、事件／路線狀態、地圖與原生 CPU 均採發起者分流；每名原真人座位則以該人的最新個人紀錄覆蓋。沒有進等待室的原真人仍載入其最新個人紀錄，但保持代理 CPU；進入等待室者改回真人。
- 集合開始後不接受非起始名單的新連線，也不接受同一 user id 同時重複進場。起始真人刷新／短暫斷線可在 30 秒內以原身分續接；逾時或明確離開後改由代理 CPU 接管，直到大家再次存檔並重新集合。
- campaign 資料不塞入既有頂層 `gameState` schema；線上 server 有 `DATABASE_URL` 時保存於 PostgreSQL `board_campaigns` JSONB，無資料庫的本機模式才使用獨立 JSON。執行中的完整玩家／地圖／戰鬥仍使用既有 `BOARD_GAME_STATE`；存檔外層 `campaignContext` 只記 campaign id、個人／集合模式、底分流與本局真人名單。

## 敵人航線出沒與等級追趕

- `public/js/board_enemy_spawn_regions.js` 是正式主遊戲與 `public/board_enemy_spawn_designer.html` 共用的區域表。設計器仍只編輯／輸出草稿，不直接改當前房間；正式預設則已由主遊戲載入，不再沿用全地圖共用敵人池。
- 一般區域只計第 2～6 排。完整字母航線（例如 B航線）包含 B 欄島嶼、B 欄縱向海格及左右兩側 A～B／B～C 海格；B西包含 B 欄本身與 A～B 海格，B東包含 B 欄本身與 B～C 海格。橫向 B～C 海格因此同時屬 B航線、B東、C西、C航線；A／G 邊界只計地圖內存在的一側。顛倒山通往第 2～6 排 A 欄的五條入口歸 A航線。
- 北四皇航線包含第 1 排與第 1～2 排間實際存在的海格，不包含第 2 排本身；南四皇航線包含第 7 排與第 6～7 排間海格，不包含第 6 排本身。島嶼敵人按島號判定區域，海格敵人按實際 route 的兩端判定；無法辨識區域的舊／特殊 route 才退回原全域後備池。
- 一周目候選為正式 `ENEMY_POOLS` 中依區域配置的 27 名一般敵人。二周目 `game.postgameWorld.unlocked === true` 後，伊姆只加入北四皇航線、麒麟格姆只加入 G西、索瑪茲只加入南四皇航線。其他四皇、劇情 Boss、推進城與固定戰役敵人不會進一般隨機池。
- 隨機出現的伊姆／神之騎士只按一般敵人戰鬥結算，不會觸發最終之島或艾爾巴夫主線。一般遭遇版伊姆的 Domi Reversi 使我方攻擊與特攻各下降一階；正式最終戰的黑轉印記與劇情機制保持原樣。
- 一般敵人島在玩家真正開始新的戰鬥時，若敵人等級低於「該玩家整船隊最高角色等級－5」，敵人會連同 HP、攻擊、防禦、特攻、特防與速度提升到此下限，且保留原剩餘 HP 比例；海格遭遇在產生敵人時套用相同下限。下限最小 Lv.1、最大 Lv.99，高等敵人不會被降低。
- 等級追趕只套用 `island.kind === "enemy"` 的新戰與一般海格；四皇、最終戰、推進城、司法島、十三 Boss、其他固定副本、PK／切磋以及同一筆 `pendingBattle` 續戰均維持原等級。區域與追趕標記放在既有 enemy profile／battle snapshot，沒有新增頂層存檔欄位或同步事件。
- 全圖鑑在角色已遇見後，會用角色 enemy key 反查同一份正式配置並顯示所有「出沒區域」；不再以「敵人島／海格航路」泛稱取代實際航線。伊姆與兩名神之騎士的區域前會加上「二周目限定」；未遇見角色仍隱藏名稱與位置。
- 圖鑑文字會合併同一字母的重疊範圍：B航線＋B東只顯示「B東」，B航線＋B西只顯示「B西」；B西與B東都有時顯示「B航線區域」。這是顯示簡化，不會合併或改動正式 `spawnRegionIds`。

## 多人地圖刷新與續戰同步

- 非房主刷新時，身分以瀏覽器原本保存的 `userId`／`clientId` 對照 server lobby；房主只作最後後備，不會因 lobby 的 `isMe` 不具裝置意義而搶走其他玩家身分。
- 擲骰動畫開始前就會保存本次最終步數。刷新後仍使用同一顆骰並在原動畫結束時間後繼續移動，不會重新擲骰、重複消耗指定骰或骰子修正；短期動畫時間只存在既有 `pendingMove`，接回後刪除。
- 海域二選一刷新會按已同步的兩個 `slotId`／`typeId` 重建本人可操作選項；其他玩家仍維持旁觀畫面，不會代替行動者選牌。
- 若目前玩家有待續戰鬥，必須等多人完整快照套用完成後才由具有控制權的玩家建立戰鬥畫面並再次同步，因此同房其他玩家都能看到接回後的戰鬥。同步端會忽略已套用版本的外部延遲重複快照，避免舊的無戰鬥畫面反過來關閉續戰；但 `turn-banner` 是先播放交棒提示再延後套用同一份快照，這個內部續跑必須放行，確保所有頁面真正切換到同一位玩家或 CPU。
- 真人與 CPU 開局招募的新角色都先完成等級／能力校正，再把目前 HP 設為校正後最大 HP；這只修正新招募初始狀態，不改同一場戰鬥的殘血續戰規則。

## 戰鬥刷新恢復

- 一般戰鬥、共鬥或二周目切磋在雙方行動已鎖定、骰子／招式動畫尚未完成時刷新，控制該戰鬥的玩家會自動接回本輪結算；不需要重新選招，也不會永久停在動畫鎖或已送出指令的等待畫面。
- 開始結算前會在目前瀏覽器分頁保存一份本輪尚未執行的乾淨暫存點。只有載回同房間、同戰鬥、同輪次及同一組行動時才可使用，最長有效 10 分鐘；結算完成、開始下一輪或離開戰鬥時立即清除。
- 暫存點屬於 `sessionStorage` 的本機恢復資料，不進入 `gameState`、手動／雲端存檔或多人完整快照 schema。沒有暫存點的舊版本中斷快照若仍保留完整雙方行動，控制玩家也會嘗試接回結算。
- 多人旁觀畫面不會自行執行別人的戰鬥；必須通過原有 `userId`、`clientId`、目前行動玩家與戰鬥控制權判斷。刷新不改變共鬥交棒或切磋的地圖回合順序，切磋結果仍不寫回主線 HP／PP。

## 招式類別圖標

- 物攻、特攻、強化、弱化、治療、護盾、控制與狀態均使用 V367 黑鐵／古金／深海色遊戲風格透明圖標；正式檔名仍為 `physical_attack.webp`、`special_attack.webp`、`buff.webp`、`debuff.webp`、`heal.webp`、`shield.webp`、`control.webp`、`status.webp`，每張 256×256。
- 圖標只負責呈現招式類別；既有類別判斷、招式效果與傷害計算均未改變。物理傷害讀取物攻圖、特殊傷害讀取特攻圖，其他類別依既有 `moveLearnTypeView()` 映射，未知類別仍以狀態圖作為後備。
- 招式學習畫面的圖標只顯示在右側現有招式卡的圓形徽章正中心，並限制於框內安全尺寸；徽章不另外顯示類型文字。中央新招式詳情的「類型」欄位則直接寫出類型名稱，只顯示文字、不重複放置圖標。

## 進化角色圖演出

## 閻魔與索隆十郎特殊進化

- 「閻魔」是 S 級不可交易角色攜帶物，效果為物攻 ×1.15、暴擊率 +8%、暴擊傷害倍率 +0.15；可單獨裝備，也可放在巴雷特的武器庫內生效。
- 目前出戰角色精確為「新世界索隆」且攜帶閻魔時，進入非切磋戰鬥會先播放閻魔試煉開場，之後才開放原本的出招、換人、道具與逃跑操作。劇情本身不扣血、不改能力、不消耗閻魔，也沒有額外操作按鈕。
- 閻魔試煉播放中會隱藏雙方血量／狀態 HUD 與中央屬性相剋圖示；畫面上方不顯示試煉標題。六張圖以 `contain` 完整顯示，不使用會裁邊的放大／位移，非相同比例螢幕以深色留邊處理；正式對話框仍覆蓋畫面下方。六幕都有新世界索隆台詞：第一幕固定為「來測試這把新刀如何。」，第五幕為「閻魔嗎……等我習慣它，就能變得更強吧。」，第六幕固定為「你也想測試我嗎？我會贏下這場戰鬥，證明給你看的。」；第二至第四幕依漫畫第 955 話／動畫第 956 集的霸氣被抽取與奪回順序改寫。六幕依序停留 3.0、3.0、2.4、2.4、3.8、4.2 秒。閻魔開場的 recovery 保護時間依六幕實際總長度計算，不得在中途提前結束；播放完成後 HUD 與相剋圖示必須恢復，才進入可操作戰鬥。
- 閻魔試煉只呈現和之國試刀、右臂被抽乾霸氣再恢復的內容；全程仍是新世界索隆，不包含羅格鎮買三代鬼徹／賭手臂試刀，也不會把角色提前替換成索隆十郎。已是索隆十郎、其他索隆型態、未帶閻魔或 PK／切磋均不播放。
- 只有目前型態為「新世界索隆」的索隆，攜帶閻魔並實際參與且贏得一場非切磋戰鬥，才永久進化成「索隆十郎」。只在船上沒有出場、戰敗、逃跑、PK／切磋、其他索隆型態或未攜帶閻魔均不觸發。
- 進化不消耗閻魔；完成後即使卸下閻魔也保持索隆十郎，但閻魔本身的物攻、暴擊率與暴擊傷害加成會隨卸下而移除。進化後換成四招專屬物理招式，並沿用既有進化型態、招式與角色資料保存，不新增 gameState 欄位。
- KING 戰勝獎勵先照原規則獨立判定 10%「KING 的佩刀」，再另外獨立判定 10%「閻魔」；兩次判定互不取代，因此可能兩件同時掉落。

## 角色／招式通用暴擊

- 暴擊只適用於目前位於我方的角色；一般敵人、CPU 與 Boss 的最終暴擊率固定為 0%。敵方招式即使帶有暴擊率加成或必定暴擊 metadata，巴雷特即使吸收狙擊瞄準鏡等暴擊兵裝，也一律只結算一般傷害。判定依目前陣營而非角色出身：原敵方角色被招募並在我方出戰後，會依自己的角色 profile、等級、進化、招式與兵裝正常暴擊。
- 正式 51 名可玩角色各自具有 `criticalRateBase` 與符合人物戰鬥形象的 `criticalStyle`，不再只依角色類型給相同基礎值。Lv.1 基礎落在 2%～18%：魔人歐斯 2%，曼雪莉／巴托洛米奧 3%，喬巴／Mr.3／伊娃科夫／裘斯 4%；索隆／羅／光月御田／比斯塔 15%，卡文迪許／奇拉／羅傑 16%，雷利／以藏 17%，鷹眼／騙人布 18%。Lv.20、40、60、80 各增加 1%，Lv.99 再增加 1%；一階進化增加 2%，二階進化增加 4%。只有沒有正式個別 profile 的自訂角色才依角色類型取後備值。
- 完整血統因子可培育的 66 種正式敵人來源身份另有逐角 profile，並依來源 `enemyKey` 套用，不會只按職能給共同值。代表值為斯潘達姆 3%、路基 19%、覺醒路基 22%、卡塔庫栗 24%、紅髮 25%、洛克斯 30%；洛克斯 Lv.1 起始即為 30%，再套用共用等級、招式、兵裝與 50% 最終上限。舊血統角色會依既有培育來源 key 自動回填新版 profile，不必重新培育。
- 最終暴擊率為角色個別基礎、等級、進化、攜帶物與招式加成相加，一般上限 50%。可增加機率的正式兵裝包含狙擊瞄準鏡 10%、閻魔 8%、疾風鉤爪 5%、櫻十・木枯 5%；59 個直接攻擊另有招式暴擊加成，並直接在技能效果列顯示「8%暴擊／10%暴擊／12%暴擊／15%暴擊／20%暴擊」。技能卡不另加角標，也不增加第五顆戰鬥按鈕。
- 只有造成直接傷害的物理／特殊招式能暴擊；輔助、治療、換人、道具與逃跑不判定。一般暴擊把該段最終傷害乘以 1.5；格里芬之劍使倍率 +0.2，赤色伯爵的傘劍使倍率 +0.1，合計倍率上限為 ×2。同一段最多只套一次最終暴擊倍率，不會因多個來源變成 `1.5^n`。
- 單段招式擲一次暴擊；多段招式每段獨立擲一次，動畫與傷害數字只在實際暴擊的段數顯示暴擊。純預覽傷害不擲暴擊，以免開啟介面就消耗隨機結果。程式已支援個別招式設定「必定暴擊」或「不能暴擊」，目前正式招式只使用 +10%／+20% 加成。
- 角色詳情顯示目前暴擊率、傷害倍率、角色特性及成長／裝備來源；戰鬥 HUD 不常駐顯示暴擊率或傷害倍率，換人後仍會在底層依新出戰角色重新計算。實際暴擊命中不顯示任何額外文字標牌；該段傷害數字使用約 92.8px 的白熱金傾斜粗體、近黑硬描邊與赤紅／暗紅／黑三層立體落影，命中第一拍短暫停頓，並在負號左側顯示原創的彎刀擊穿四芒羅盤星小圖示。圖示桌機約 40px、932×430 平板約 26px，只由戰鬥頁顯示，不參與傷害判定；普通傷害、MISS、治療與被擋下不顯示。戰鬥頁不會重新判定或修改傷害。等級與進化沿用既有資料，不新增存檔欄位。

## 推進城同層組隊與逃獄

- 位於同一樓層不代表已組隊。只有目前回合玩家能從既有「目前小隊」欄邀請同樓層、未加入其他隊伍且沒有待處理邀請的真人；發出邀請後完成本回合。受邀者在自己的回合接受才建立隊伍，拒絕或接受本身不消耗該回合，之後仍可正常抽事件。
- 成隊後，每回合仍由當前玩家負責抽事件與決定整隊下一層路線。一般事件作用於仍在同樓層的正式隊員；「隱藏囚犯」只讓抽中事件的當前玩家個別抽取，不會被隊長或其他隊員拿走。隊伍全員的所有船員 HP 與所有招式 PP 都全滿時，事件池排除伊娃科夫；任一隊員有回復需求時重新加入。
- 非牢外救援的推進城戰鬥使用既有共鬥交棒：同樓層正式隊員每個戰鬥輪各行動一次，即使玩家在全域回合順序中不相鄰也不會把中間的非隊員加入。戰鬥後的獎勵與路線決定只給仍未倒下、未逃出的參戰隊員。
- 單一隊員全隊 HP 歸零時先進入兩次該玩家本人回合的待救援，不會立刻讓全隊逃獄失敗；只有所有參戰隊員都倒下才全隊押往海軍本部。若原本的牢外玩家選擇救援囚犯，該場仍是救援者單獨作戰：勝利釋放目標，失敗只把救援者押往海軍本部。
- 組隊 id、邀請與戰鬥狀態都保存於既有玩家／戰鬥快照，隨完整 `BOARD_GAME_STATE` 同步；不新增 localStorage key、Socket.IO event 或推進城第五顆操作按鈕。

## 巴雷特的武器庫

- 「巴雷特的武器庫」使用相容 id `bullet_large_bullet_armor`，本身占角色原本 1 個攜帶物欄；玩家從既有攜帶物整備介面開啟武器庫後，可固定裝入兩件背包中的其他角色攜帶物。兩件效果同時生效，且各自保存觸發次數、護盾、累積量等戰鬥狀態。
- 武器庫不能裝入另一個武器庫，兩個兵裝槽也不能放入相同 id 的攜帶物；例如戰鬥服＋九尾幻面可以，兩件戰鬥服不行。第一槽卸空不會讓第二槽移位。裝入時該件物品會從背包扣除，卸下單槽會歸還該件物品；舊存檔若已有重複兵裝，保留第一槽並把後一件退回背包，最大 HP 類效果改變時按原生命比例換算目前 HP。
- 卸下或替換整個武器庫、持有者離隊時，兩件內裝物與空武器庫都回到背包。舊「大型子彈號裝甲」依其他存活船員增傷／減傷的效果已不再使用。
- 巴雷特戰開場吸收武器庫時，只在持有者對應的六孔位置取得空武器庫外殼；內裝兩件兵裝不展開，也不會把任何效果交給巴雷特。兩件兵裝仍保存在原持有人身上，但該武器庫孔被破壞前維持封存，包含最大 HP 在內的能力都不生效；第一骰對應的直接攻擊命中並破壞該孔後，兩件兵裝才同時恢復生效。
- 戰鬥狀態列只顯示一顆「巴雷特的武器庫」，不直接攤開兩件兵裝。點擊武器庫後，才在同一個詳情浮窗內選擇兵裝 1／兵裝 2，查看所選兵裝的目前狀態與完整效果；這只是顯示收合，兩件兵裝仍依規則同時生效。
- 2026-08-26 全量回歸確認 93 件可內裝兵裝都能正確使用兩個槽位、獨立 runtime、序列化與卸回，且玩家效果處理為 93／93；V317 找出的十件 Boss 遺物缺口已補齊。疾風圍巾只依正式 effect 套用一次速度 +25%，不再重複乘算；單獨裝備與武器庫內裝規則相同。
- 武器庫沿用既有角色攜帶物、背包及完整戰鬥／遊戲快照；沒有第五顆戰鬥指令或獨立的解除按鈕。

## 十件 Boss 遺物的玩家端戰鬥規則

- 櫻十・木枯：速度與物理攻擊永久各 ×1.2，另增加 5% 暴擊；每場第一次受到直接攻擊時，整個多段招式的傷害均降低 40%。換人再上場不重置。
- Gran Tesoro 黃金戒：每個實際造成傷害的直接招式累積一層黃金，多段整招只算一層。三層時使敵人束縛一回合，防禦與特防各下降一階並持續整場；每場只觸發一次。持有人獲勝時，該玩家取得的戰鬥基礎貝里額外 +200%，即基礎 100 會成為 300；共鬥依各自是否持有分開計算。
- Battle Smasher：每次直接攻擊命中累積一點熱量，第三次只進入過熱完成；下一次直接攻擊傷害 +40% 並無視 20% 防禦，命中或落空都會消耗過熱，結算後反噬裝備者最大 HP 30%，但最低保留 1 HP，之後熱量歸零重蓄。
- 魔王樂譜：只作用於一次行動中的多段直接攻擊，從第 1 段起依 +1%、+2%、+4%、+8% 持續翻倍，沒有段數上限；每次新招式都從 +1% 重算，單段招式不加成。
- 七星劍：依裝備者目前已損失的最大 HP 計算，每完整損失 5% 使直接攻擊傷害 +4%；1 HP 附近最多計 19 階，即 +76%。
- KING 的佩刀：戰鬥開始為背火。背火時受到直接攻擊傷害 -25%，被直接命中後熄火；熄火時速度 ×1.25，下一次直接攻擊傷害 +25%，完成直接攻擊後復燃。落空也視為完成直接攻擊；治療、道具或換人不會復燃。
- 三叉戟「土龍」：特攻永久 ×1.3。敵人連續兩次行動都使用相同 id 的直接招式時，第二次必定落空並立刻受到自己最大 HP 40% 的反擊；中間使用治療、強化等非直接行動會中斷記錄，每場只發動一次，反擊可致死。
- 赤色伯爵的傘劍：暴擊傷害倍率 +0.1；每個直接招式全部段數結算後，只依敵人實際扣除的總生命吸取 20% 一次；超過缺少生命的部分轉成護盾，護盾最多為最大 HP 15%，並優先承受之後傷害。
- 鐵雷「Ragnir」：特攻永久 ×1.2。每個造成傷害的直接招式生成一朵冰雲；第一骰為 5／6 時，出招前已有的每朵雲使傷害 +15%。第三朵生成當下立即使敵人凍結一回合並清空全部冰雲，再重新累積。
- 森森生命種子：回合結束時若裝備者低於最大 HP 70%，回復最大 HP 3% 並累積一顆種子，最多三顆。受到致命傷時一次消耗全部種子，依 1／2／3 顆回復最大 HP 12%／24%／36%；每場只能復活一次。復活用掉後仍可觸發低血回復，但不再累積無法使用的新種子。

## 巴雷特六孔吸收道具的同次命中順序

- 玩家直接攻擊成功命中巴雷特時，先讓當下仍在六孔內的受擊型攜帶物結算本次效果，再依第一骰破壞對應孔位並歸還道具；被打中的孔不能因先破壞而跳過自己的最後一次儲存、反傷或觸發效果。
- 道具歸還原船員時會保留本場一次性使用狀態與儲存量。傑爾馬66戰鬥服在致命傷落地前發動「不屈」，本次傷害降低為 0 並提升防禦、速度；傷害被完全擋下仍屬於成功命中，所以骰面對應孔位照常破壞。
- 戰鬥服孔位卡會顯示「不屈：待命／已發動」，破壞歸還後仍看得到本場是否用過。巴雷特吸收戴彭九尾幻面後，每次攻擊都改為克制目前目標的屬性，套用正式屬性倍率，並於戰鬥訊息、敵方效果、紀錄與六孔詳情顯示「九尾幻化」及目前克制關係。
- 上述六孔先後順序與九尾提示只屬巴雷特戰；一般戰鬥只共用傑爾馬66戰鬥服原有的致命傷保護及新增的「不屈」視覺。

## 連線房間刷新恢復

- 連線遊戲刷新後必須先向房間取得既有完整 `BOARD_GAME_STATE`，不可因房間名單先抵達就建立新地圖或返回選角。
- 只有伺服器明確回覆房間沒有遊戲快照、且目前裝置具備初始建立權時，才由房主建立新局；一般玩家仍等待房主的唯一初始快照。
- 同一個持久 `clientId` 重新連線時，初始化期間送回的既有快照仍必須套用；完成恢復後才重新啟用「忽略自己送出的回傳」與正常回合推送。
- 第一份既有快照只恢復真正的待續移動、選擇及戰鬥資料，不延用舊頁面已失去計時器的移動／骰子／結算／離場動畫鎖；若目前輪到 CPU，快照完成後只由房主重新啟動 CPU 自動步驟。
- 第一份既有快照必須先於快照內的舊回合提示套用；舊 `turn-banner` 不得延遲刷新恢復或重播。正常快速刷新不顯示等待視窗，也不改寫目前 `turnStep`。
- 超過 2.4 秒仍未取得房間快照時才顯示連線等待說明；初始狀態請求使用遞增間隔且最多四次，不得無限要求全量快照。此限制只屬本機首次連線追蹤，不寫入存檔。

## 地圖視覺模式

- 正式地圖預設使用原始藍色海圖模式；復古航海圖模式只在明確選用時調整海面、島嶼、海上裝飾、路線與海格的色調，玩家船、標記、文字、回合框、工具列與其他 UI 不受影響。
- `map_visual=original` 可完整顯示修改前的原始地圖樣式，`map_visual=vintage` 顯示復古版；此選項是本機純顯示設定，不改變地圖座標、事件、可走路徑、玩家狀態、存檔或多人同步結果。

## 單字代用圖示顯示規則

- 角色戰鬥屬性是玩法資訊，保留原本的彩色文字：`力` 為紅色、`速` 為藍色、`技` 為綠色，無屬性顯示中性色 `無`；主遊戲、一般戰鬥、特殊戰鬥及中央相剋提示使用同一規則，不使用屬性圖片圖示。
- 修行六能力、船隻五升級、司法島突破補給、推進城事件及其他純功能符號仍以圖片辨識，不以單一中文字冒充圖示。
- 放在圓框或固定圖示洞內的透明素材，必須依可見 Alpha 圖案而不是整張畫布置中，並保留四邊安全距離；桌機、平板與手機皆須以正式頁截圖檢查後才能完成。
- 船團與全圖鑑概要、黑色遭遇格、島嶼／副本／道具圖片載入失敗時也使用正式圖示備援；備援只影響顯示，不改變事件、獎勵或道具效果。
- 骰面點數、S～E 階級、Lv、回合／數量、約克線索撲克牌牌面及未解鎖圖鑑 `????` 是玩法資料或保密資訊，並非代用圖示，因此維持文字顯示。

## Board CPU 名稱

- Board 等待室與正式遊戲最多三名自動玩家，依 CPU slot 固定顯示為 `CPU1`、`CPU2`、`CPU3`。
- 移除 CPU 後重新加入會沿用可用 slot；名稱不影響 CPU 身分、回合、自動操作、同步或存檔資料。

## 新招式學習類別圖示

- 新招式學習與招式替換介面以圖片區分物攻、特攻、強化、弱化、治療、護盾、控制與狀態八種類別；類別名稱保留為輔助標示，不再用一個中文字充當圖示。
- 類別圖檔本身只保留中央符號與能量光效，不繪製額外外框或黑色底盤；版面既有的圓形圖示格負責承載與對位。
- 圖示只改顯示方式，實際物攻／特攻仍使用正式招式分類規則，其他效果技仍依原本 `category`／`type` 判定。

## 遊戲狀態

主狀態在 `public/js/board_game.js` 的 `state.gameState`。

主要內容包含：

- `seed`：遊戲亂數種子。
- `boardData`：地圖、島嶼、路線、海域、標記。
- `players`：玩家、船、角色、道具、位置、金錢、懸賞、狀態；`yorkDecoderTier` 保存該玩家目前最高的約克座標解碼器階級。
- `phase`：目前遊戲階段。
- `round`：目前回合數。
- `currentPlayerIndex`：目前行動玩家。
- `turnStep`：回合中的步驟。
- `availableCards`：可招募或使用的角色池。
- `yonkoStatus`：四皇據點狀態。
- 特殊區域狀態：司法島、推進城、Marineford、水之七島、最終島等。

讀檔會經過 `normalizeLoadedGameState()` 補齊舊存檔缺少的欄位。

### 圖片式彈窗與長清單操作

- 同一種彈窗因點選項目、裝備、更換、領取或即時資料更新而重新產生時，可捲動清單必須保留玩家當前位置；資料筆數減少時最多只收斂到新的清單底部，不能跳回頂端。
- 背包、攜帶物、訓練素材、外觀框、任務簿、圖鑑、競技場、酒館、船員／船隻相關長清單不使用強制捲動吸附，滑鼠、卷軸與觸控都以玩家實際停留位置為準。
- 切換到不同種類的彈窗不繼承前一個彈窗的位置；關閉後重新進入仍依該入口原本的預設選項開啟。卷軸位置只屬前端暫時 UI，不寫進 `gameState`，也不增加多人同步資料。

### 一般戰鬥畫面時序

- 真人、CPU 與自動觀察戰鬥都先由戰鬥 iframe 依序播完我方／敵方開場台詞；CPU 必須等 `intro-done` 後才可選招，不能用自動流程略過對話。
- 正式戰鬥頁開啟後，每個招式只使用 iframe 的「準備→擲骰→攻擊→命中」視覺時間線；舊主地圖 modal 動畫不再疊播。這不改雙方每輪各一次行動、CPU 選招、擲骰或傷害結算。
- 開場被動即使會降低敵方能力，也只播放狀態發動圖與能力下降特效，不視為一次直接攻擊。
- 直接攻擊的受擊圖、瀕死圖、顯示 HP 與傷害跳字都以每段真正接觸為準；接觸前須保持攻擊前人物圖與 HP。

## 開局與選角

全新遊戲建立完成、尚未產生選角順位時，會先播放「大航海時代」開局序章。內容依序呈現羅格鎮處刑、羅傑以「想要我的財寶嗎」及「去找吧」兩段作品原意台詞開啟大航海時代、遺言傳遍世界後眾人為財富／名聲／力量與夢想出航、海上衝突、玩家抵達出發港，再用航海圖介紹四種夥伴職能；序章結束或玩家按下跳過後，才進入原本的隨機選角順位與三輪蛇形選秀。序章只介紹共通職能效果，不介紹每張角色卡自己的被動能力。

四種職能的開局說明沿用正式隊伍效果：戰鬥型會在攻擊時爭取追加戰鬥骰，數量越多越容易發動；偵查型會逐步揭露鄰近島嶼、遭遇格與海格選項情報；移動型提高移動骰上限、戰鬥速度並提供逃跑機會；輔助型降低受到的戰鬥傷害，並在每輪結束時回復全隊生命。同職能人數增加會強化對應效果，但角色自己的 `passive` 仍在選角卡與角色資料中查看。

序章使用既有全螢幕劇情播放器的自動、速度、返回、繼續與跳過控制。是否已看過只以遊戲 `seed` 記在目前瀏覽器工作階段，不寫入 `gameState`；重整同一局或手動讀檔不會把序章重新插回正式流程。多人模式會先等待房間初始 `BOARD_GAME_STATE` 快照，操作方與觀看方可各自控制本機劇情速度或跳過；同一種子的 `setup-order` 更新會保留仍在觀看的序章，房主推進到 `setup-draft` 時才依正式狀態同步關閉。

序章後的順位與三輪蛇形選秀改用全螢幕港口招募介面。先顯示 1～4 名玩家的隨機順位與每位玩家三個船員席位；四人局的順位板只顯示四個固定玩家欄頭，再以三列呈現正序、逆序、正序共十二次抽取狀態，不重複排列玩家頭像與姓名。四個玩家欄與十二個狀態格只排列在航程底圖的中央羊皮紙內，不覆蓋左側輪次木牌或右側望遠鏡裝飾。接著由目前選角玩家轉動 S／A／B／C／D／E 六區命運轉盤；轉盤視覺結果仍對應原本的 1～6 隨機值與 `T1`～`T6` 招募階級，因此角色池、階級機率與候選不足時的既有降階規則不變，也不允許重新轉動來改結果。

## 地圖

地圖由 `createMapTemplate()` 建立，並可由 `public/js/board_map_layout_override.js` 或 localStorage 內的 layout 覆寫座標。

目前地圖包含：

- 起點：Loguetown。
- Reverse Mountain 與五條分支。
- 7x7 主島嶼格。
- 四皇角落據點。
- Marineford。
- Water Seven。
- 司法島。
- 推進城。
- 最終島與後期解鎖路線。
- 島嶼間 route 與 sea tile。

地圖渲染由 `renderMap()` 負責，會畫出島嶼、路線、海域格、裝飾、標記與玩家船隻。

真人玩家第一次抵達顛倒山、且尚未占有主航線時，會先播放顛倒山登山劇情，再回到地圖選路；CPU 與已選過主航線的玩家略過重播。顛倒山固定提供第 1～第 5 海路，採先選先占的唯一占用制：玩家只能點選目前亮起且尚未被其他玩家占用的航線。若本次移動仍有剩餘步數，選定後會先消耗一格駛入該航線，再繼續走完剩餘步數；沒有剩餘步數時停在航線入口。此劇情不新增進度欄位，是否已看過由玩家既有 `claimedBranchId` 判斷。

地圖標記存在 `gameState.mapMarkers`，每位玩家最多保留 1 個標記。查看島嶼或海格時，若該格已是自己的標記，按鈕會顯示「取消標記」並清除；若自己已在別處有標記，按鈕會顯示「改標這裡」，旁邊會提供「取消原標記」。標記與取消都只影響自己的標記，線上局仍透過一般 `BOARD_GAME_STATE` 快照同步。

偵查情報只依查看地圖的玩家目前位置計算：偵查型被動第 1 階在島上時揭露直接相鄰島嶼，在海路上時只揭露目前海路的兩端；第 2 階才會把目前相連航路或所在航路的遭遇海格標成黑色；第 3 階揭露海格選項。偵查台不能單獨找出遭遇格：沒有開啟偵查第 2 階時，即使偵查台升滿，地圖仍不顯示黑格，逐格點擊普通海格也只會得到未知海格資訊。偵查第 2 階已標出的黑格本身不寫敵人姓名；偵查台 Lv1 以上的玩家點擊黑格後，才會看到該格敵人的姓名與圖像。沒有偵查台時仍只知道黑格有敵影。Lv2 會在船隻真正停靠遭遇格後、開戰前補充敵人階級、等級、屬性、類型與 HP；Lv3 的敵島基本情報只對玩家目前所在的敵島，或目前位於上述偵查範圍內的敵島生效。海格敵人使用本輪敵影刷新週期、格子與玩家組成的穩定亂數，點擊預覽與實際停靠會鎖定同一名敵人；若該敵人屆時正在其他戰場，才沿既有保留規則換人。

## 移動

正常回合中玩家透過 `rollDice()` 擲骰。

移動骰基礎範圍為 1～6；隊伍每有 1 名移動型船員，上限增加 1，職能被動最多計算 3 名，因此正式最高為 1～9。第 4 名以上移動型不再提高移動骰上限、戰鬥速度或逃跑門檻。一般擲骰會播放約 2.4～3.2 秒的全螢幕骰面滾動，停止後讓結果保持 3 秒再消失並開始移動；指定步數券仍直接顯示路線與可到達格，不播放隨機骰動畫。

移動流程：

1. 檢查目前是否可行動，例如是否正在戰鬥、動畫中、特殊區域中、被鎖定或已跳過回合。
2. 建立 `pendingMove`。
3. `continueMove()` 逐步消耗步數。
4. 若從島嶼離開，進入 route。
5. 若路線分岔，開啟路線選擇。
6. 若經過 Reverse Mountain，依目前規則開啟分支選擇。
7. 若抵達島嶼或海域，依剩餘步數與事件決定是否繼續。
8. 步數結束後呼叫 `resolveLanding()`。

船隻移動動畫以逐格呈現為主，標準每步約 0.32 秒，符合 0.25 到 0.35 秒的可讀節奏。CPU / 測試快轉只縮短每步等待動畫，不改擲骰、路線、落點或事件結果。

落點分派：

- 海域：`resolveSeaTile()`，可能觸發海戰、事件、寶箱、buff 等。
- 一般島嶼：事件、任務、商店、招募、醫院、酒館等。
- 敵島：進入戰鬥。
- 四皇島：四皇據點戰或相關事件。
- 特殊島嶼：司法島、推進城、Marineford、Water Seven。
- 最終島 / 最終門：後期終局流程。

海格事件二選一維持原本類型卡背選擇流程，操作方選卡後直接揭曉結果，直接遭遇海格則維持原本敵影預覽與進入戰鬥流程。`SEA_CARD_EFFECTS` 目前分為金錢、天氣、寶藏、藥物與遭遇；金錢與寶藏獎勵會依海域區域與回合數放大，天氣會明顯改變航程或下回合骰值，藥物事件改成百分比回復 / PP 回復或較有感的副作用。海格事件卡背圖片獨立放在 Board 專用資料夾 `public/images/board/game/sea_cards/backs/`。

寶箱海格 / 寶箱海域會直接進入四選一寶箱流程；所有寶藏類海格也都改成抽寶箱，不再直接給固定道具或扣道具。寶箱抽選與揭曉使用全螢幕舞台式 overlay，不把寶箱圖放在一般對話框卡片裡。系統會依該寶藏事件的權重，從木、銅、銀、金、寶石 5 種寶箱中獨立抽出 4 個候選寶箱，候選可以重複同類型；接著先展示 4 個寶箱正面與類型，玩家按下「確認洗牌」後才會全部翻成相同黑影背面並洗牌，最後才讓玩家選 1 個揭曉。木寶箱必定是陷阱，會隨機造成貝里損失、HP 損失或 PP 損耗；銅箱以上才是獎勵箱。寶箱圖片路徑預設為 Board 專用資料夾 `public/images/board/game/sea_chests/` 下的 `chest_back_shadow.webp`、`chest_wood.webp`、`chest_copper.webp`、`chest_silver.webp`、`chest_gold.webp`、`chest_gem.webp`；缺圖時會顯示文字 fallback。

寶箱權重採「每一個候選寶箱獨立抽出」比例，因此 4 個候選中可以出現多個同類型寶箱。標準 / 寶箱海域為木 42、銅 28、銀 17、金 9、寶石 4；漂流寶箱群為 46 / 29 / 15 / 7 / 3；航路券寶箱為 36 / 32 / 20 / 9 / 3；護符寶箱為 30 / 30 / 24 / 12 / 4；被撬過的寶箱為 58 / 27 / 10 / 4 / 1；假寶藏箱為 64 / 24 / 8 / 3 / 1；沉船寶庫為 18 / 24 / 30 / 20 / 8；古代遺物寶箱為 12 / 20 / 30 / 25 / 13。

玩家抵達島嶼時會先彈出島嶼徽章 HUD，再進入後續落點流程。常見分類顯示為商店、酒館、任務、敵島；醫院、副本、最終島、顛倒山等特殊落點會顯示對應標籤，避免把特殊島誤標成一般服務島。

## 角色

角色資料來源是 `public/js/board_cards.js`，輸出 `window.BoardCards`。

角色資料包含：

- id、名稱、稀有度或 tier。

- 基礎能力與成長。
- 招式資料。

### 技能設計規則

技能資料來源是 `public/js/board_cards.js` 的 `moveSet`、`evolutionForms[*].moveSet` 與 Lv.50 到 Lv.95 的後期技能產生流程。

目前規則：

- 保留既有 move id，避免影響存檔、音效對照、特效對照與戰鬥紀錄。
- 每位基礎角色都要有 Lv.1 可造成傷害的起手招式。
- 起手招式依角色特色命名，例如斬擊、踢擊、拳、槍、醫療、屏障、天候、花花果實等；若角色在原作有明確招式名，優先使用動畫 / 漫畫出現過的名稱。
- 進化形態與後期招式優先使用原作招式、果實能力、霸氣類型或明確出現過的戰鬥動作；不再為了湊數或去重自動加上熟練、進階、高階、終式、終擊、新世界等後綴。
- 人工審閱清單校正後，正式招式名稱以 `public/js/board_cards.js` 為準；目前二檔魯夫使用「巨人槍」、四檔使用「坦克人」、新世界香吉士使用「魔神風腳」。
- 自動產生的後期技能若沒有可信名稱可用，會直接略過該補招，避免產生自創招式。
- 有下一階進化的角色或形態，只能學到下一階進化所需等級以前的技能；達到進化等級後，要先進化才會開放下一批招式。
- 一般進化不會立刻把上場 4 招全部換成新形態招式；進化後會保留原本已帶的技能，並只把第一個真正新的進化招式加入待學習佇列，玩家可在船上的新技能提示中選擇要替換哪一招或暫時不學。
- 進化形態後續招式會從進化等級開始依序分配到更高等級，等角色升到對應等級後才會進入學習 / 替換流程。
- 除了基礎角色的開局自帶招式與五檔・尼卡覺醒直換招式外，同一角色 / 形態在同一等級最多只會排入 1 招升級學習招式；沿用進化前同一 `moveId` 的招式不會排入新招佇列。
- 五檔・尼卡屬於特殊覺醒例外，覺醒時會直接切換為五檔預設招式，不走一般進化的一招替換流程。
- 五檔・尼卡自動覺醒影片播放前會先暫停目前 BGM，影片正常結束或 fallback 後再恢復戰鬥 / 地圖 BGM，避免影片音軌和背景音樂重疊。
- 五檔・尼卡正式上場後，船員詳情會把 `五檔・尼卡框` 列為該角色專屬可選外觀框；既有或新覺醒的五檔若尚未手動選過框，會預設使用尼卡框。獨立戰鬥頁會在選中此框時套用尼卡專用日光、左右白煙與方框配件；角色名字文字保留，但不再顯示名牌底圖或雲冠底圖。這只是戰鬥視覺，不改覺醒條件、技能、屬性、HP 或同步資料。
- Lv.50 到 Lv.95 的後期技能只會加到無進化角色或該角色目前進化線的最終形態，中間形態不會先學後期招。
- 同一角色的整條進化鏈輸出前會檢查技能名稱，避免基礎角色、進化形態與後期技能出現同名技能。
- 每段進化後完整可學的最高傷害招式應不低於進化前形態的最高傷害招式；一般進化剛完成時因為會保留舊招，不要求新形態第一招立刻取代原本最強招。
- 目前拳、踢、斬、槍、爆炸、火、雷、冰、水、風、幽靈、衝擊波等類型可由既有命中特效與音效推斷處理，不需要新增素材才能運作。
- 傷害招式另有獨立 `damageClass` 判定，不再直接把舊 `category: special` 當成特攻。物攻使用攻擊／防禦，特攻使用特攻／特防；狀態、治療、護盾與控制技不屬於兩種傷害類別。
- 特攻招式在所有玩家可見名稱前加 `(特)`；物攻不加前綴。正式例：鬼斬為物攻、`(特) 龍捲風` 為特攻；首肉踢擊為物攻、惡魔風腳與魔神風腳為特攻；猿王槍為物攻、猿神槍為特攻。
- 防禦能力階級必須依實際 key 說明：`def` 顯示「防禦」，`sdef` 顯示「特防」，同時變動時兩者都列出；特攻能力 `satk` 顯示「特攻」。不得再以模糊的「意志」代替特防，或只寫「增加防禦」卻實際修改 `sdef`。
- 舊存檔相容以穩定 move id／正式招式名重新解析傷害類別，不改招式 id、PP、解鎖等級、既有 category 或完整快照結構。

可選補強素材：

- 磁力 / 金屬系命中特效與音效，給基德使用。
- 屏障系命中特效與音效，給巴托洛米奧與防禦技能使用。
- 花花果實系命中特效與音效，給羅賓使用。
- 煙霧、沙、重力、歌聲 / 音波、荷爾蒙系命中特效與音效，讓斯摩格、克洛克達爾、藤虎、烏塔、伊娃科夫更有辨識度。

## 道具

道具資料來源是 `public/js/board_items.js`。

主要輸出：

- `window.GAME_ITEMS`
- `window.ITEM_SHOPS`
- `window.ITEM_EVENT_POOLS`
- `window.ITEM_DROP_POOLS`
- `window.ITEM_DROP_RATES`

道具類型包含：

- `navigation`：移動、導航、路線或海域相關道具。
- `battle`：戰鬥中或戰鬥前後使用的消耗品。
- `ship`：船隻裝備或改造材料。
- `held`：角色攜帶道具。
- `key`：劇情、任務或四皇 / 最終流程需要的關鍵物品。

道具圖片預設遵循 `images/board/items/<itemId>.webp` 這類 id 對應路徑。改 id 會同時影響背包、商店、掉落、任務、戰鬥與素材引用。

「單數骰子」`odd_dice` 與「雙數骰子」`even_dice` 是 B 級戰鬥消耗品，可從道具商店或進階補給池取得。使用時在既有道具面板內選擇我方或敵方；接下來 2 次該側行動的第一顆戰鬥骰，只會從 1／3／5 或 2／4／6 中抽取，第二與第三顆追加骰不受影響。同一側已有奇偶效果時，新使用的骰子覆蓋舊奇偶並把剩餘次數重設為 2；效果圖示會在對應側顯示奇偶與剩餘次數。多人時我方效果依使用者分開，敵方效果由同一 Boss 共用；狀態跟隨既有 battle snapshot。Tot Musica 的左右世界仍各自選行動，道具選擇會保留指定陣營；若用在 KING，KING 仍照實際被控制後的第一骰排定下一回合背火，不會公開他的隱藏判定規則。

「交棒海賊旗」`relay_pirate_flag` 是 A 級角色攜帶物，可從道具商店或寶藏池取得。持有者完成攻擊、戰鬥道具或澤法解除炸藥岩行動後，必須先讓敵我本輪正常結算；若持有者仍存活、仍在場上且有其他存活後備，才使用既有替補介面讓玩家自行選擇下一名船員上場。Tot Musica 戰保留雙世界限制：只沿持有者所在的現實／歌世界隊列自動換上下一名存活船員，不會跨世界挑人。交棒不視為瀕死，不消耗海賊旗，也不讓新角色補做本輪行動；手動換人、持有者已瀕死、已被其他機制換下或沒有可用後備時不觸發。

指定步數券從背包選定 1～6 步後會立即接入本回合移動流程，不需要再按一次「擲骰前進」。若所在島嶼有多條可走航線，地圖會直接亮出可選路線與對應海格；選定後依指定步數繼續移動。此道具不播放隨機骰動畫，也不套用一般擲骰才會觸發的船隻移動加成。

海上列車黃金票屬於不消耗的重要道具。從背包使用時，可以在目前所在島標記終點；之後使用時會提供標記島作為可選目的地。水之七島是黃金票的固定停靠點，即使尚未標記島嶼也能選擇前往；若標記島就是水之七島，目的地清單只顯示一次。搭乘後會播放海上列車地圖動畫，抵達後直接進入該島落點 / 服務流程。

戴彭的九尾幻面是四皇對策攜帶道具。裝備者攻擊時，攻擊屬性會永遠轉為克制目前敵人的屬性；若敵人有閃避上升，也保留干擾預判的命中輔助與降閃避效果。對紅髮香克斯時，這會讓攻擊直接轉成克制目前轉相的屬性，不再使用舊版「每 3 回合 1 次打錯轉相補成 x1.3」規則。

四皇對策攜帶物包含戴彭的九尾幻面、格里芬之劍、無畏之心、太陽海賊團的徽章。這些道具屬於重要攜帶物，不能賣掉，也不會作為一般商店道具流通；但裝備到角色身上後可以卸下或更換給其他船員使用。舊存檔若曾把這些道具記成 `bound`，主流程也會允許卸下並回到背包。

船員詳情、船員管理列表與攜帶物選單中的裝備 / 卸下操作，成功後會刷新同一個面板而不是直接關閉；玩家可以立刻確認目前攜帶物、背包數量，或繼續替同一名船員更換。攜帶物選單會提供「返回」與「關閉」：從船員詳情進入時返回同一名船員詳情，從船員管理列表進入時返回列表並保留該船員展開；從主畫面快捷入口進入時，返回等同關閉。

### 全破後 Boss 攜帶物

史基至洛克斯共 14 件 Boss 攜帶物已建立正式道具 id、名稱、圖片與效果參數，詳細表格見 `docs/POSTGAME_BOSS_RELICS.md`。這 14 件不加入一般戰鬥隨機掉落池。史基至綠牛的前十三名 Boss 每次勝利會對每位實際參戰者各自進行固定 10% 專屬攜帶物判定；觀看方不判定，同一場的同一玩家最多判定一次，重複挑戰可再次取得，且道具不可交易。

洛克斯的名刀「日蝕」沒有解碼器時已有 10% 基礎掉落率；持有一階、二階、三階約克座標解碼器後分別為 20%、30%、40%。每次洛克斯勝利仍會按每位實際參戰者自己的階級獨立判定；觀看方不判定，同場同玩家防重，重複挑戰可再判定。名刀「日蝕」不可交易，也不取代完美血統核心、25 研究點數、私人血統抽取、首次外觀框或其他既有結算。

覺醒黑焰羽衣由角色裝備時，最大生命與戰鬥速度各提升 30%；裝備、更換或卸下會保留角色原本的目前生命比例。名刀「日蝕」使裝備者的攻擊與特攻各提升 20%，並強化既有戰鬥型被動的追加骰：第一顆達原門檻 6／5／4 並成功擲出第二顆後，第二顆分別需達 5／3／1 以上才追加第三顆；三顆相加計算倍率。1～11 點維持原倍率；12 點為 ×2.05，13～18 點每多 1 點再增加 ×0.15，依序為 ×2.20／×2.35／×2.50／×2.65／×2.80／×2.95。隊伍沒有戰鬥型追加骰資格、第一顆未達原門檻，或第二顆未達日蝕門檻時都不會出現第三顆。正式戰鬥頁會以金色骰面／紅黑霸王色專屬圖顯示第三顆，定格時只爆發一次；合計畫面同列保留三顆各自外觀與點數。

若上場角色攜帶戴彭的九尾幻面，且角色原屬性沒有克制目前敵人屬性，戰鬥頁會在戰前對話與開場被動演出結束後、玩家可操作前播放九尾幻面發動演出：道具圖飛向角色圖後消失，接著我方屬性欄在力 / 速 / 技間輪轉約 2 秒，最後停在克制敵人的屬性。若原屬性已經克制敵人，則不額外播放這段演出。

傑爾馬66戰鬥服的一般持有者，每場第一次受到致命直接傷害時會完全擋下該次傷害，並讓防禦、速度各提高 1 階。若持有者是第二階進化的「新世界香吉士」，戰鬥服只會在他成為目前上場角色且該回合確實能選擇戰鬥指令時啟動，時機與九尾幻面一致；一般換人或瀕死替補若已消耗該輪行動，只顯示原型態上場，下一個可行動回合開始才播放變身。主戰鬥卡在變身動畫開始前與完整五秒演出期間都保持「新世界香吉士」名稱及原 `sanji_evolution_2` 圖，演出結束後才切成「新世界香吉士・隱形黑」與隱形黑圖。卸下戰鬥服或不是新世界形態時維持原角色資料。隱形黑使用七張專屬 normal／angry／hit／hit_enemy／morale／weak／dizzy 戰鬥圖；防禦、意志、速度分別在新世界形態數值上再乘 1.30／1.25／1.35，攻擊與戰術不再額外提高，避免與專屬招式威力重複放大輸出。速度高於敵人時傷害提高 15%；若招式本身另有「速度高於敵人」增傷，兩者不相乘，只採用較高倍率。進場與「隱形・消失／隱形黑・空中加速」會啟動光學迷彩，使下一次敵方直接攻擊必定落空；四個預設招式替換成隱形・消失、隱形黑・流星蕎麥麵、隱形黑・急襲連踢、戰鬥服・地獄回憶，已學會的海步行與魔神風腳也會投影為對應的隱形黑版本，PP 仍寫回同一招式。

光學迷彩另使用第八張 `stealth.webp` 演出圖：平時與迷彩待命期間都維持 `normal.webp` 一般隱形黑立繪；只有敵方直接攻擊確實被光學迷彩判定為 MISS 的當下才短暫切到半透明隱形圖，MISS 演出結束後自動恢復 `normal`。使用「隱形・消失」或「隱形黑・空中加速」只會重新準備必閃，不會立刻改變待機立繪。

## 戰鬥

戰鬥主邏輯在 `public/js/board_game.js`，戰鬥 UI 也可能透過 `public/board_battle.html` 與 `public/js/board_battle.js` 顯示。

所有正式戰鬥招式選單只顯示資料定義的「威力」，不再顯示會隨角色能力、敵方防禦、屬性、狀態與骰子即時變動的可能傷害區間；零威力的強化、治療、護盾與控制招式維持顯示效果內容。這只改變玩家看到的招式資訊，正式傷害計算、CPU 選招所需的內部資料、骰子、暴擊與結算不變。

敵方專屬戰鬥框只根據敵人的穩定 `key` 決定，不是玩家可裝備或需要解鎖的獎勵。黑鬍子、紅髮香克斯、大媽與凱多會分別套用既有四皇四層框；十三座無風帶 Boss 島的史基至綠牛則各套用自己的單張透明框並隱藏普通敵方紅框。敵方凱多沿用既有四張素材與外側配件位置，但使用獨立的敵方顯示 ID，中央紫黑雷雲固定為 20% 不透明度，避免蓋住臉與上半身；玩家解鎖並裝備的四皇凱多框仍保留原核准參數。這個框 ID 會寫進所有觀看端共用的 battle view，因此真人操作、CPU 操作、共鬥觀看與一般觀看都顯示同一套敵框；框本身不改 HP、傷害、掉落、回合或控制權。

角色外觀框是玩家解鎖、船員個別裝備的戰鬥視覺獎勵。玩家已解鎖框款存於 `ownedCosmeticFrameIds`，每張船員卡目前裝備的框存於 `cosmeticFrameId`；船員詳情可開啟「選擇外觀框」，在無框、該角色可裝備的已解鎖框，以及角色專屬框之間切換。司法島通關會解鎖 `黃金電話蟲框`，頂上戰爭篇成功救援會解鎖 `3D2Y 框`，推進城打倒麥哲倫會解鎖 `推進城・毒龍框`，首次打倒黑鬍子 / 大媽 / 凱多 / 紅髮香克斯會分別解鎖對應四皇框；四皇四張都取得後會解鎖 `四皇全倒框`，擊退伊姆會解鎖 `空白王座框`。五檔・尼卡會額外看到角色專屬 `五檔・尼卡框`。四檔魯夫、新世界索隆、新世界香吉士、新世界娜美、狙擊王、新世界騙人布、新世界喬巴、新世界羅賓、新世界羅、凱洛特月獅型態、靈魂之王布魯克與佛朗基將軍也各自有角色專屬框，通常只有對應進化形態可選，且新取得 / 舊存檔同步時若尚未手動選框會預設套用；例外是 `狙擊王框` 可在騙人布從狙擊王進化成新世界騙人布後保留並繼續選用，`四檔魯夫框` 可在魯夫覺醒成五檔・尼卡後保留並繼續選用。未進化到對應階段的角色仍不能直接裝備後階框。新解鎖通用框時會自動套給目前隊伍中尚未裝框的船員，之後玩家可逐一調整。舊存檔回補會同時檢查正式道具、司法島 `clearCount` / `cleared` / 島嶼擊破狀態 / 舊 log、Marineford 的 `win` / `rewards` / 正式道具 / 舊 log、麥哲倫討伐紀錄 / 舊 log、玩家自己的四皇首勝 glyph、拓本欄位與拓本道具、`finalGateDefeated` / `finalGateDefeatedBy` 與伊姆擊退 log，避免舊紀錄道具已開掉時漏補。正式戰鬥頁只在玩家卡顯示目前上場船員選中的外觀框；五檔・尼卡只有在選中 `五檔・尼卡框` 時才顯示尼卡專用框，若選四檔魯夫框、3D2Y、黃金電話蟲、其他可用框或無框則照選擇顯示。

戰鬥流程：

1. `startBattle()` 由敵島、海域、四皇、特殊副本或最終戰觸發。
2. `createBattleState()` 建立敵我 combatant、招式、狀態、portrait、log、回合資料。
3. `startBattleRound()` 處理回合開始效果、狀態、被動、船隻、Boss 特殊規則。
4. 玩家選擇行動，敵方依規則行動。
5. `computeMoveDamage()` 計算傷害。
6. 戰鬥結束後 `finishBattle()` 結算獎勵、掉落、任務進度、特殊區域進度或失敗流程。

所有正式直接傷害在受擊圖成立時會於實際受擊者上方跳出傷害數字；連續攻擊每一下各自顯示。普通傷害使用黃橙色字；暴擊使用較大的白熱金數字，並在數字上方顯示深紅／近黑斜切金邊「爆擊」銘牌，標牌與數字同步彈入。未命中顯示 MISS，回復使用綠色字。這些演出只反映 `board_game.js` 已完成的正式判定，不會在戰鬥頁重新擲骰或改變傷害、回合、狀態與同步結果。

戰鬥、任務與副本若透過核心經驗流程發放 EXP，會依角色狀態分配：當前出戰且未瀕死的角色拿完整 EXP，其他存活船員拿 95%，瀕死船員仍可拿 50%。每位角色再依隊伍平均等級套用低等追趕倍率；若該角色攜帶幸運海鷗蛋或其他 `exp_bonus_self` 攜帶物，最後會對該角色實得 EXP 追加 30% 等道具倍率。等級與新招學習仍照各角色自己的經驗曲線與技能解鎖等級處理。

一般敵島與海域遇敵只使用可重複出現的普通敵人池。副本 / 劇情專用敵人不得再重複放入一般池；目前麥哲倫只屬於推進城，青雉、黃猿、赤犬只屬於 Marineford，斯潘達姆只屬於司法島。一般 T1 敵人池目前留空，隨機選敵會往鄰近階級的一般敵人回退，避免抽到副本 Boss。

多人非共鬥戰鬥中，若上場角色瀕死且仍有替補，玩家必須先選下一位上場；替補上場動畫播完後，該玩家本次戰鬥回合結束，戰鬥進度保存為 `pendingBattle` 並交棒給下一位玩家。替補角色不會補做被擊倒角色尚未執行的行動。單人測試局仍會在替補後直接進入下一輪。

共鬥戰鬥中，每位參與者完成一個行動或瀕死替補後，都必須先完整播放「輪到誰」交棒橫幅；橫幅尚未結束前會用 `battle.coop.handoffPending` 暫時鎖住戰鬥行動，避免原玩家在真正切到下一位前再次選招、逃跑或使用道具。若交棒目標的上場角色也已瀕死，會先切到該玩家的替補選擇，再繼續後續行動。已逃跑或已戰敗離場的共鬥 runtime 不能保留 `needsReplacement`，避免離場玩家又被拉回替補選單。

共鬥戰鬥頁的玩家 HUD 下緣提供本機「共鬥視角」切換，而且只對本場實際參戰者顯示。清單會標出目前操作玩家、觀看中的玩家、自己、待命、倒下與撤離狀態；點擊參戰者只會改看該玩家 runtime 的上場角色、HP、狀態、能力階級、攜帶物與角色圖，不會把操作權交給觀看者，也不算一次換人或一個回合。共鬥交棒到下一名玩家時，所有參戰者的畫面都會自動切到新的操作玩家，即使之前正在手動觀看別人。不是自己的操作權時不能選招、換人、用道具或逃跑；即使畫面正顯示目前出手者，仍須通過原本的本機身分控制權判斷才可操作。視角選擇不寫入 `gameState`、battle snapshot、localStorage 或 Socket.IO。

共鬥支援只開放戰鬥道具，船員技能不會跨玩家作用。使用單體補血、異常解除、技能次數回復或復活道具時，可以指定任一仍在本場共鬥中的玩家及其船員；全隊治療道具必須先指定一名玩家，效果只涵蓋該玩家的船員。道具由目前行動玩家自己的庫存扣除，並消耗其完整戰鬥行動；若是替別人使用，敵方仍以目前行動玩家的上場船員為本次敵方行動目標。每場使用上限按玩家與道具分開計算，不會因隊友已用過同名道具而被共用額度。

共鬥參戰者全隊瀕死時會進入 `待救援：2回合`，不會立刻被送往推進城。這兩次只計算該名倒下玩家自己的後續待救援回合；本人可在待救援回合消耗自己的復活道具自救，其他參戰者也可在自己的回合消耗完整行動與復活道具救援。選擇「等待救援」才會把自己的剩餘次數由 2 扣到 1、再由 1 扣到 0；第二次仍未復活時只有該名玩家永久退出本場共鬥，其他存活參戰者繼續。待救援 runtime 會隨 round-pause 保存到 `pendingBattle`，地圖全隊瀕死檢查不會提前處置。若所有仍可恢復的參戰者都已倒下，而且任何待救援者都沒有可自救的復活道具，戰鬥立即判定失敗。

一般共鬥與司法島特殊共鬥的戰鬥 HUD／結果會使用相同資訊語意：顯示參戰人數，並在結算逐人列出傷害、承傷、治療、行動、使用道具、完成救援與個人獎勵。血統因子抽取仍由每位實際參戰者各自操作，但不再把所有真人鎖在同一個戰後等待頁；共鬥勝利時只有目前大富翁回合的玩家可以選擇提取並查看結算，其他真人的個人抽取 entry 與戰鬥結果會排入自己的待結算佇列，輪到本人回合才自動開啟。尚未輪到的隊友與觀看方不顯示提取／獎勵頁且不能送出指令；本人確認延後結算後回到地圖繼續同一回合。共同獎勵在原勝利出口只發放一次，延後查看不會重複取得。

多人結算的每位玩家固定使用五列卡片：第一列是玩家名稱，第二列是傷害／承傷／治療，第三列是行動／道具／救援，第四列是貝里／懸賞金，第五列是 EXP／道具。這只是顯示結構，數值與獎勵來源仍是原 battle snapshot；單人結算維持四張獨立獎勵卡。

正式戰鬥頁以 1024×576 為邏輯畫布；可視區較小時會維持比例縮放並置中，平板直向仍顯示完整戰鬥畫面，手機直向則先顯示橫向裝置提示。這只調整顯示方式，不改變共鬥回合、救援次數、道具消耗、控制權或同步規則。共鬥血統因子等待卡在平板直向可於圖片框內捲動，不會遮住返回操作。

普通敵島與海格戰即使只有一名參戰者，也會沿用共鬥 runtime。玩家逃跑骰成功時，結果必須維持為 `escape`，不能因為戰場上已沒有仍在作戰的參與者而改判 `lose`；成功逃離不會送進推進城。從敵島逃離的玩家留在目前島嶼，並記住登島時的 `entryDirection` 與來時 route，下一次航行只能沿該航線原路返回；多人全部撤離時，每位成功逃離者都套用自己的原路返回狀態。

部分角色有開場被動，會在新一輪戰鬥開始時立刻套用自我 buff 或敵方 debuff，例如敵方攻擊、命中、速度或防禦下降。這些效果不是上一場殘留；觸發時戰鬥紀錄會明確寫出「開場被動」與造成的能力變化。新戰鬥若有戰前對話，會等對話播完後再播放角色發動被動的出招 / 狀態演出，演出結束前不能先選招。debuff 類開場被動可使用發動者的攻擊姿勢來表現霸王色或壓制，但這只是純演出：不改敵方 HP、不跳傷害數字、不切受擊圖或瀕死圖；真正傷害仍須等正式選招與擲骰後的 attack 事件。戰鬥頁的 buff / debuff 圖示會等被動或招式文字與狀態特效出現後才顯示，避免圖示搶在演出前暴雷。續戰 / pending battle 則會保留原本戰鬥中已存在的能力階級與狀態。

戰鬥中最後一擊造成瀕死時，角色會先維持受擊圖到招式演出結束；戰鬥頁不會只因快照 HP 已為 0 就提前切換 `dizzy`，必須等正式瀕死事件才切瀕死圖、播放淡出與替補流程；已淡出的瀕死角色不應被舊的 portrait timer 重新顯示回場上。綠牛首次致命例外為攻擊演出完成後先顯示 HP 0 與倒下圖，再播放種子發芽回血，不會在攻擊還沒打完時先回血。

受擊圖的方向依角色在本場戰鬥的實際站位決定，不依角色原始資料屬於玩家或敵人。站在玩家側時使用 `hitPlayerSide`，站在敵方側時使用 `hitEnemySide`；因此競技場中的玩家角色與血統因子培育後上船的原敵人，都會使用面向該側攻擊來源的受擊圖。舊存檔或舊快照若沒有方向欄位，仍回退原本的 `hit` 圖；此規則只改畫面，不改傷害、命中、回合或角色陣營。

獨立戰鬥頁的斬擊類命中特效會依攻擊方與受擊方方向播放：玩家攻擊敵人時從我方側掃向敵方，敵人攻擊玩家時從敵方側掃向我方。此方向性只套用於 `slash_single.webp`、`slash_multi.webp`、`wind_slash.webp` 等斬擊 / 風斬圖；拳、火、雷、冰等爆點型命中特效仍在受擊位置原地爆發。

戰鬥、任務或副本結算若取得重要道具並觸發道具展示 HUD，回合交接會等展示動畫進入可點擊狀態且玩家點擊收下；若同時有多個重要道具，會等整個展示佇列播完後才執行 `endTurn()` 與下一位玩家橫幅。

四皇戰採原總血量內的疊層血條，不把四皇原本 900 多 HP 變成兩條 900 多 HP。血量高於半血門檻時視為上層血條，主遊戲戰鬥 modal 與 `public/board_battle.html` 只顯示同一條血條；血條會縮短一點，右側只顯示 `X2`，並用新色表示還有上層血。畫面上的 HP 文字只顯示目前這一條血的血量，也就是總血量約除以 2 後的當前層數字，避免 HUD 同時顯示總血量與 `X2` 造成混亂。打到半血門檻時不會直接判定勝利，而是播放第二階段對話，並清除四皇身上的能力階級、狀態、回合效果與各四皇專屬 buff / 場地累積，例如香克斯見聞蓄勢、凱多龍鱗與覺醒、大媽魂壓、黑鬍子暗穴場地 / 捕獲等。第一條血被打爆時，本次攻擊超過第一條血的溢出傷害不會延續到第二條，第二型態一律從最後一條滿血開始。剩最後一層時血條回到原本紅橘色且不再顯示額外文字；這層歸零才會進入正常勝利結算。第二階段後若敵方回復或再生，HP 也會被限制在最後一層的半血上限內。凱多進入第二型態後，正式戰鬥頁的待機、攻擊、受擊、士氣、虛弱與瀕死圖會整組切到 `yonko_kaido_phase2/`；已在第二條血的舊戰鬥快照若仍保存第一型態路徑，讀取戰鬥 view 時會依既有 `phase2` 狀態修正，不改任何戰鬥數值。

伊姆最終門戰的血條 HUD 也使用同一套單條疊層顯示：總 HP 不翻倍，第一層顯示目前層血量並在右側顯示 `X2`，進入第二型態後改顯示最後一條血且移除 `X2`。第一條血被打爆時同樣不延續溢出傷害，第二型態從最後一條滿血開始；此規則不改伊姆原本技能與傷害倍率。

戰鬥進場對話正式資料在 `public/js/onepiece_prebattle_lines.js`。進場時會先以角色實際形態與敵人尋找專屬配對，再使用角色／敵人台詞池；四皇、伊姆、神之騎士團與十三 Boss 區域另有 22 組後期敵人台詞池及 25 組高關聯配對。正式選句會排除「上場、出戰、迎戰、登場」等系統播報字眼，也不允許角色直接說明每回合、骰子、血量、命中率或「超越這份見聞色」等遊戲規則／能力解說句；若沒有專屬句，角色會先沿用該形態現有配對中最常用的自然口吻，最後才依戰鬥／偵查／移動／輔助類型與敵人定位使用自然備援句。`prebattle_dialogue_redesign_list.tsv` 與 `prebattle_dialogue_text_list.txt` 是人工審閱清單，不是執行時的正式資料來源。

獨立戰鬥頁的戰前對話會自動播放，以維持多人觀看同步，開戰前對話不提供跳過按鈕。四皇第二階段對話仍可保留本機跳過控制；此跳過只影響本機視覺等待，不改戰鬥結果、回合順序、`battleState` 欄位或 Socket.IO event。

傷害計算目前會考慮：

- 等級。
- 招式威力。
- 攻擊 / 防禦能力。
- 骰子或隨機倍率。
- 屬性倍率。
- 護盾。
- 能力 stage。
- 狀態效果。
- 被動效果。
- 攜帶道具。
- 船隻加成。
- 四皇、最終戰或特殊 Boss 規則。

## 任務

任務資料來源是 `public/js/board_missions.js`。正式任務分為「一般個人任務」與「主線任務」，共同任務已移除。

一般個人任務分級包含 E、D、C、B、A、S。玩家最多同時持有 6 件一般任務，每次任務島拜訪最多接取 2 件；可在任務日誌領獎或放棄。任務資料會定義：

- id。
- grade。
- title。
- type。
- condition。
- 獎勵金錢。
- 懸賞。
- 道具獎勵。
- note。
- goal。
- options。

任務 goal 透過字串 kind 與資料描述，例如海域步數、拜訪島嶼、開寶箱、海戰、使用道具類型、角色經驗或等級、擊敗敵島、司法島階段、四皇勝利、Marineford、推進城、攜帶道具觸發、擊敗指定 tier 或惡魔果實敵人等。

任務進度依多處事件回報更新，修改 goal kind 或事件名稱前要全域搜尋。

主線任務共有 12 章、120 話，從完成開局選角開始，依序引導玩家經過顛倒山、一般島嶼、船員養成、水之七島、司法島、推進城、頂上戰爭、四皇、艾爾巴夫、伊姆與最終結局。規則如下：

- 每位玩家各自擁有一條主線，資料保存在玩家的 `mainMission`；不占 6 件一般任務上限。
- 同一時間只有一話主線生效。條件達成後，真人要在正式任務日誌領取獎勵才解鎖下一話；一次操作會繼續領取當下已完成的後續話數，避免只為領獎反覆開關日誌。CPU 會自動領取，但同一次事件最多只領一話。
- 主線不可放棄。完成全部 120 話後，日誌顯示「主線全破」。
- 真人主線進度同時讀取正式事件統計與目前遊戲狀態，因此舊存檔載入後會從第一話開始，但已具備的船員數、懸賞、船體改造、司法島／推進城／頂上戰爭／四皇／最終篇狀態可在對應話數解鎖時直接判定。
- CPU 解鎖下一話時，只有海格、戰鬥、取得／使用道具等真正會累加的事件才把當下絕對進度記為 `goalBaseline`，只計啟用後新增的進度；船員數、懸賞、島嶼發現、船隻改造、副本與結局旗標等狀態型條件永遠直接讀目前值。載入舊快照時，版本 3 正規化會移除不再適用的狀態型基準。
- 主線貝里、EXP 與道具依 `BOARD_MAIN_MISSIONS` 的固定值發放。第 1～10、11～20、21～30 話的基礎 EXP 分別為原設計值的 35%、50%、70%，第 31 話後保留原值；日誌顯示基礎 EXP，實得仍受船員成長補正與後排分享影響。主線懸賞不套用一般任務或戰鬥的最低 1,000 萬賞金增幅。
- 四個懸賞主線門檻分別為 2.5 億、5 億、12 億與 30 億；門檻均高於解鎖前主線本身已發放的懸賞，必須再透過戰鬥、任務或其他正式來源累積。
- 第 41～44 話在進入水之七島改造門檻前，合計提供 20 個船材木板與 4 個船匠工具箱。第 116 話只在伊姆第一條血量真正打破、戰鬥進入第二階段時完成。第 120 話除宴會餐盒外，永久授予不可消耗、不可交易的重要道具「黎明航路生命卡」。
- 主線額外獎勵不取代司法島寶箱、麥哲倫、頂上戰爭、四皇拓本或最終結局等既有正式獎勵，也不重複發放這些劇情關鍵物。
- `mainMission` 會進入手動存檔與完整 `BOARD_GAME_STATE` 快照。舊存檔沒有此欄位時會安全建立；舊快照若仍含 `sharedMissions`，只做相容性保留，正式任務牆、日誌與進度系統都不再顯示或處理共同任務。

## 副本與特殊區域

特殊區域大多在 `public/js/board_game.js` 中保存規則與狀態，部分有獨立頁面或 UI script。

### 司法島

司法島是特殊 raid 流程，含階段、敵人、獎勵與相關任務進度。修改時要同時檢查地圖落點、戰鬥結算、任務 goal 與存檔欄位。

司法島戰鬥與一般多人節奏一致：參與者完成一個戰鬥回合後要交棒給下一位玩家。若一招擊破目前階段敵人，流程必須先完整顯示階段獎勵 / 隨機 buff，再讓擊破者選定下一階段要上場的角色；選完後只初始化下一階段共享敵人，結束該玩家回合並等待下一位玩家行動。輪到已參與司法島且仍在司法島的玩家時，若 raid 仍進行中，主遊戲會用目前共享 HP / 狀態自動開啟司法島戰鬥，即使該玩家沒有舊的 `pendingBattle`。

CPU 抵達司法島且有存活船員時不顯示真人的發起／加入選擇：未開戰或已通關時直接從斯潘達姆重開討伐，已有進度時直接加入目前共享階段並建立自己的司法島 battle。真人仍保留「發起討伐／加入討伐／暫不挑戰」選擇。

司法島通關獎勵除了既有寶箱、貝里、賞金與 EXP，也會解鎖外觀框 `黃金電話蟲框`；新通關時會自動套給目前尚未裝框的隊伍船員。

### 推進城

推進城使用 `board_game.js` 內的狀態與規則，並由 `public/board_impel_down.html`、`public/js/board_impel_down.js` 提供獨立 UI。主頁與副本頁透過 snapshot / command 類資料橋接。

多人逃獄採本文件「推進城同層組隊與逃獄」規則：同層玩家要先邀請並由對方接受才組隊；當前玩家抽事件／選路線，戰鬥依同層正式隊員逐一交棒，隱藏囚犯則維持個人抽取。

推進城中擊退麥哲倫時，除了既有移動 / 逃出選項，也會解鎖通用外觀框 `推進城・毒龍框`；舊存檔會用麥哲倫討伐紀錄與舊 log 回補。

### Marineford

Marineford 是特殊戰役 / Boss 流程，相關資料與結算在 `board_game.js`，另有 `public/board_marineford.html` 頁面。修改時要檢查 Boss、獎勵、戰鬥結束與任務觸發。

處刑台倒數目前為 40 回合。每打完一名 Marineford Boss，會依該場戰鬥實際經過的回合數扣除倒數；若救援尚未完成，擊破非最終 Boss 後會獲得 1 顆救援骰。玩家可在頂上戰爭頁面右上「剩餘回合」旁自行選擇時機擲出救援骰，擲出 1d6 後將結果加回所有尚未救出 / 未處刑的處刑台倒數。若倒數已到 0 且手上有救援骰，必須先擲骰爭取時間才能進下一戰；若沒有救援骰則救援失敗。舊版 20 回合存檔載入時會升級到新版倒數，進行中的處刑台角色會補上差額但不重置已經扣掉的進度。頂上戰爭頁主要流程由目前敵人卡片接續：未開戰時點擊會依狀態進行抽籤、選處刑台或開始救援；救援中點擊則進入目前 Boss 戰。

多人局中，Marineford 戰鬥也要遵守「完成一個戰鬥回合後交棒」節奏。戰鬥頁結果出現並播完動畫後，主遊戲會自動呼叫既有結算流程，不需要玩家再按返回地圖。若本輪沒有擊破 Boss，戰鬥會保存為該玩家的 `pendingBattle`，保留 Boss 目前 HP、狀態與上場角色；下次輪到該玩家時自動續戰。若擊破青雉、黃猿或赤犬，會推進到下一名 Boss 但先交棒，等該玩家下一回合再回到頂上戰爭頁繼續；若擊破最後的戰國元帥，則不再交棒等待下一回合，會立刻清除戰鬥並回到 Marineford 成功救援畫面。單人測試則會在自動結算後回到 Marineford 頁面。

Marineford 成功救援獎勵包含既有 `3D2Y 的報紙`，並會解鎖外觀框 `3D2Y 框`；新通關時會自動套給目前尚未裝框的隊伍船員。

### Water Seven 船隻改造

Water Seven 是船隻改造與服務相關區域，另有 `public/board_water_seven.html`。修改船隻、船隻裝備、材料、商店或服務時，要同時檢查 `board_items.js` 與主遊戲內的船隻加成套用。

### 四皇據點

四皇狀態在 `yonkoStatus` 一類資料中維護。四皇戰會影響首通、獎勵、Road Poneglyph、最終島或最終門條件。四皇相關改動要檢查戰鬥結算、關鍵物品、任務、地圖解鎖與多人同步。

四皇首次打倒時，除了 Road Poneglyph 拓本與四皇對策攜帶物，也會解鎖對應通用外觀框：黑鬍子框、大媽框、凱多框、紅髮框。玩家四張四皇框都取得後會解鎖 `四皇全倒框`；舊存檔會用玩家自己的 `defeatedYonkoGlyphs`、`roadPoneglyphs`、拓本道具與已擁有四皇框回補。

CPU 玩家抵達四皇據點時會走與真人相同的四皇劇情 / 機制面板；面板出現後會依 CPU 策略判斷是否挑戰，判斷要挑戰時自動按下進入戰鬥，判斷尚未整備或非主線目標時可自動暫不挑戰。

四皇據點、最終島、最終門 / 艾爾巴夫 / 伊姆戰後等共用全螢幕劇情播放器，右上角提供「自動 / 速度 / 跳過」控制。自動播放速度可在 0.5x、1x、1.5x、2x、3x 間切換並保存在本機；速度只縮短劇情文字等待與下一句鎖定，不改戰鬥、掉落、回合或同步結果。最終之島啟動儀式與羅賓讀取段落會套用同一速度設定，並提供跳過直接進入後續揭示。

艾爾巴夫篇劇情分為重逢、神之騎士團突襲、麒麟格姆戰後、索瑪茲戰後、喬巴治療、伊姆降臨、伊姆戰內黑轉支配、艾爾巴夫託付、下一條航路，以及接在艾爾巴夫收束後的革命軍瑪麗喬亞支線。伊姆降臨劇情結束後會先進入伊姆戰鬥頁；戰鬥開場對話與被動效果處理完後，伊姆才在戰鬥中施放 `Domi Reversi・黑轉支配`。戰鬥頁會用被抽離船員的半身圖，以戰鬥 portrait 同尺寸從玩家角色圖後方抽出；抽出圖在玩家角色中心時保持不可見，離開原本角色卡後才顯示，靠近伊姆時先停在伊姆旁邊，翻轉階段才進入伊姆整張戰鬥卡中心後方，因此不會遮住原本出戰角色或伊姆。伊姆本體保留黑轉配件但不套黑轉暗化 / 褪色濾鏡，只有被支配船員在完成惡魔化後會暗化。視覺播完才切入被支配船員戰。瑪麗喬亞支線會先以「同一時間，在瑪麗喬亞……」過場切入，再分為聖地前線與盤古城深處兩幕；前半使用戰火中的瑪麗喬亞背景，薩波與克爾拉離開戰場後，盤古城深處背景才從「兩人穿過崩塌的神之地。」開始。

多人局的艾爾巴夫神之騎士團戰鬥遵守一般多人戰鬥節奏：完成一個戰鬥回合後會自動保存進度並交棒給下一位玩家；若擊敗麒麟格姆或索瑪茲，勝利結果頁會自動完成結算並先交棒，該玩家下次輪到時才接續麒麟格姆戰後 / 索瑪茲戰後劇情與下一場戰鬥。單人測試局維持原本連續播放戰後劇情並直接進入下一段。

紅髮香克斯的轉相戰仍會要求玩家打出克制目前轉相的屬性；若上場角色裝備戴彭的九尾幻面，攻擊屬性會直接幻化成該轉相的克制屬性，因此命中轉相時使用正常克制倍率 x2，不再有冷卻或 x1.3 補正。

紅髮香克斯四皇據點的戰前劇情分為「久別重逢的宴會」、「騙人布與耶穌布」、「正事開始」、「約定之戰」四段：草帽一行人與紅髮海賊團先以宴會重逢，騙人布與耶穌布短暫對話，最後魯夫向香克斯提出索取紅色歷史本文並進入約定之戰；具體轉相、見聞蓄勢與神避規則仍放在紅髮情報 / 機制面板。

黑鬍子四皇據點的戰前劇情分為「抵達黑鬍子據點」、「黑暗吞噬」、「雙果實的震動」三段，重點是黑鬍子與草帽一行人的對峙、艾斯相關挑釁、暗暗果實與震震果實的壓迫畫面；具體戰鬥規則仍放在黑鬍子情報 / 機制面板，不混進劇情台詞。

大媽四皇據點的戰前劇情分為「甜點王國」、「被撞破的寶物庫」、「茶會了結」三段：草帽一行人潛入萬國，羅賓完成紅色歷史本文拓印後被大媽撞破，最後以香吉士、甚平與魯夫正面迎戰收束；具體靈魂拷問與霍米茲規則仍放在大媽情報 / 機制面板。

凱多四皇據點的戰前劇情分為「重返鬼島」、「百獸殘影」、「跨過我吧」三段：草帽一行人重返鬼島，確認紅色歷史本文在鬼島深處，最後與守在石碑前的凱多正面對峙；具體龍鱗、破鱗與覺醒規則仍放在凱多情報 / 機制面板。

四皇據點與最終島劇情的角色半身圖共用 `public/images/board/story/speakers/`。黑鬍子劇情中魯夫、甚平 / 吉貝爾與娜美可使用新的憤怒半身圖 pose，避免艾斯相關挑釁仍套用一般嚴肅或震驚表情。紅髮劇情已接入重逢、父子對話、正事開始與約定之戰四張專屬背景，並新增魯夫、香克斯、騙人布、耶穌布、班貝克曼、拉奇魯、娜美、索隆、香吉士與羅賓等紅髮段落用 speaker pose；拉奇魯的丟肉笑臉與調侃魯夫搶東西台詞分別使用不同 pose。伊姆戰後瑪麗喬亞支線已接入薩波、克爾拉、龍、馬卡斯·馬茲聖、托普曼·沃裘利聖、伊特贊巴隆·V·納斯壽郎聖、謝潑德·十·彼得聖與費加蘭德·加林聖半身圖；前三位在伊姆倒下前使用正常版半身圖，伊姆倒下後新增崩壞台詞並切到 `crumbling` pose，謝潑德·十·彼得聖與費加蘭德·加林聖維持崩壞圖。耶穌布半身圖因完整長槍占用畫布，顯示時會套用 1.3 倍專用放大補正；騙人布父子對話的 `conflicted` pose 因素材偏特寫，顯示時會套用 0.7 倍並往上移 24%，讓人物比例與位置接近其他紅髮角色。

CPU 玩家在開局隊伍未滿或平均等級仍低時會進入保守選路：優先找酒館補齊隊伍與必要補給，並降低高風險敵島、司法島、推進城與 Marineford 的路線權重；等隊伍數、HP / PP、平均等級與戰力達標後才恢復副本與高難度目標評分。

CPU 玩家自動學招與戰鬥選招時，必須讓上場技能組保留至少 1 招可造成傷害的招式；純治療、buff、護盾或 power 為 0 的特殊支援招不算攻擊招。若舊存檔或自動學招造成目前上場角色沒有可用傷害招，CPU 戰鬥中會先嘗試補回可攻擊招式；補不回時才換上其他仍有可攻擊招式的存活船員，避免輔助角色只補血 / 上 buff 而打不完。

多人局中，新海格遭遇與敵島重新佔據時會避開目前仍在戰鬥中或 pending 戰鬥中的 enemy key，避免不同玩家在不同地點同時打到同一個敵人。若是同一敵島或同一海格格子的接續戰 / 共鬥，則視為同一場戰鬥，可以共用同一敵人與進度。

獨立戰鬥頁的觀戰同步會保留 KO 淡出後的隱藏狀態：同一名 0HP 角色在瀕死動畫消失後，不會因後續 `battleState` 推送或面板重繪重新顯示 hit / dizzy 圖；只有換上新角色、復活，或切換到另一場戰鬥時才重置。

### 最終島 / 最終門

最終島與最終門是後期解鎖流程。地圖會在條件達成後補上最終島相關 route 或 layout。最終戰與 Imu / Final Gate 相關規則在主遊戲戰鬥與結算流程中。

啟動最終之島時，系統會從最終島 layout 選出的連接點建立最後航路；這個連接點就是最終之島前一個島，會轉為「艾爾巴夫」。轉換時會清除該島原本的敵島、商店、任務或暫時服務狀態，改成 `elbaph` / `finalGateAnchor`，並在最終之島解鎖後對所有玩家可見，避免仍顯示成未知島嶼或舊島種。

玩家抵達艾爾巴夫並觸發終局流程時，會先進入巨人島重逢與神之騎士團突襲劇情，不會立刻播放伊姆降臨地圖動畫。劇情採用使用者定稿台詞：草帽一行人先與巨人族重逢，麒麟格姆與索瑪茲突襲西村並抓走孩子，玩家依序救回孩子、斬開荊棘、由喬巴替眾人重新包紮補藥。只有在麒麟格姆與索瑪茲都被擊退、索瑪茲戰後劇情中的喬巴治療完成後，主地圖才會在艾爾巴夫節點播放伊姆降臨動畫，動畫結束後進入伊姆出場並先建立伊姆 final gate 戰鬥。

艾爾巴夫終局順序是神之騎士團先、伊姆後：玩家抵達艾爾巴夫後，會先看到麒麟格姆與索瑪茲突襲西村，再依序進入麒麟格姆戰與索瑪茲戰。索瑪茲戰後劇情中，喬巴緊急治療會插在孩子救回後、戰場短暫安靜下來前；此時全隊 HP / PP 回滿。治療完成後，地圖上才播放伊姆降臨動畫，接著伊姆詢問索瑪茲與麒麟格姆為何失敗，魯夫確認伊姆是幕後首領。之後先進入伊姆 final gate 戰鬥，戰鬥開場對話與開場被動結束後，伊姆在戰鬥頁內施放「Domi Reversi・黑轉支配」；戰鬥頁會從玩家角色圖後方抽出被選中船員的完整角色卡，抽到伊姆角色圖後方前不淡入、不壓暗、不旋轉，抵達後才切到前景原地翻轉，接著伊姆圖退到後面、被選中船員翻到前面並展開惡魔化方框、左右翅膀、紅眼與名牌，演出播完後系統才從目前玩家隊伍中挑出最低等且可抽離的一名船員作為敵方，切入 `final_gate_black_turn` 支配戰。被支配船員會使用自己的已學招式並套用原本半身圖與惡魔化配件，原隊伍中的該船員暫時以 0 HP 不可上場。支配戰遵守一般多人戰鬥節奏，未打完一回合會保存 pending battle 並交棒；擊敗後不發一般敵島 / 最終戰獎勵，被支配船員會解除支配回到隊伍，接著才開始伊姆本戰。若隊伍只剩一名可用角色而無法安全抽離，會在施法後跳過支配戰並直接進入伊姆本戰，避免卡死。艾爾巴夫銜接恢復只在沒有戰鬥、沒有移動且未被劇情鎖定時執行；索瑪茲戰後劇情或伊姆降臨動畫正在播放時不會再重啟同一段銜接。

擊退伊姆並打開通往最終之島的航路時，玩家會解鎖通用外觀框 `空白王座框`；舊存檔會用 `finalGateDefeated`、`finalGateDefeatedBy` 或伊姆擊退 log 回補。

最終之島的完整結局是每名玩家各自第一次登島的內容。玩家自己的 `finalEndingCleared` 或 `finalEndingRecords[player.id]` 已存在後，再次登上拉夫德魯不會自動重播劇情，也不會再次觸發結局、任務或全房解鎖獎勵，而是進入「黎明紀錄殿」。紀錄殿顯示個人結局、通關回合、十三種 Boss 線索、線索總數、約克解碼器與蛋頭島定位進度；真人玩家可舉辦免費黎明宴會，完整恢復船上全員 HP、PP 與能力階段且不消耗回合，整備後仍可請大熊轉送；只有確認轉送或主動離開紀錄殿才會結束目前停靠流程。尚未親自通關的其他玩家仍保留自己的首次結局。

本遊戲所稱的「二周目」是同一局完成最終之島後開啟的終局世界，不要求另建房或重開新局。首次全房通關會同步開放艾斯、柯拉松、光月御田與羅傑的一般酒館招募資格；研究所與血統因子仍沿用原本終局世界開放條件，不再另外增加角色鎖。

已通關玩家可在黎明紀錄殿請抵達最終之島的大熊使用肉球果實轉送。目的地頁「大熊的肉球航路」以曾經取得過的十三張約克 Boss 線索牌作為永久座標；線索牌第一次進入該玩家背包時就登錄，交易取得同樣有效，而交易、販出或其他方式失去實體線索後，已登錄的 Boss 座標不會消失。舊存檔會從目前背包中的線索安全補登，未曾取得的牌維持鎖定。

- 玩家必須人在拉夫德魯才能把目的地交給大熊；選定十三座 Boss 島之一後，當下只登記座標為 `awaiting_turn`、結束本回合並顯示下一位玩家。這一步不播放伸掌、全螢幕或地圖飛行動畫，玩家船仍停在拉夫德魯，不會提前消失或移到目標島。
- 到該玩家下一個個人回合才進入 `arriving`：原船 token 隱藏，玩家船疊在淡冰藍外殼、黃綠核心的側向肉球壓力氣泡中，從拉夫德魯沿單一完整貝茲曲線慢速飛往本局真正配置該 Boss 的孤島，鏡頭逐幀跟隨。落點顯示大型碗狀撞擊坑、放射裂槽、副坑、碎石與煙塵，動畫完成後恢復原船 token，再沿用登島介紹、共鬥邀請與 Boss 戰流程。要再次轉送，必須先循一般地圖航線回到拉夫德魯。
- 肉球轉送只提供一次性的延遲移動，不在世界地圖新增永久捷徑，也不改變 Boss 島與四皇島可沿來路離開的規則。蛋頭島／洛克斯仍使用原本十三線索解碼器與五海格航路，不列入十三個可選目標。
- CPU 重訪拉夫德魯時，若有已解鎖 Boss 指針，優先前往尚未取得其專屬掉落的 Boss；全部專屬掉落都已持有時，再依目前船員屬性適性選擇。完全沒有 Boss 指針時才使用黎明宴會作為 fallback。
- 永久座標保存在玩家的 `unlockedPostgameBossClueItemIds`，延遲轉送保存在 `pendingPostgameBossVoyage`；新流程正常只寫入 `awaiting_turn`／`arriving`，載入舊版 `departing` 時會安全轉為等待且不補播選島動畫。兩者都跟隨既有完整 `BOARD_GAME_STATE` 玩家快照、存讀檔與正規化流程，不另設 localStorage key 或 Socket.IO event。

### 拉夫德魯後：無風帶消失與十三座孤島

房間中任一位玩家完成拉夫德魯正式結局後，會觸發一次全房共用的世界事件：無風帶消失。演出先從約克趁聖地戰亂逃走開始；她帶走十三座秘密據點的座標、培育資料與遠端控制核心，返回蛋頭島後才啟動設施。接著播放無風帶崩解、十三島顯現、約克部署與蛋頭島移動；約克全程是遠方獨白，不會和拉夫德魯現場的魯夫一行人隔空對話。十三座培育槽甦醒時會回傳確認碼，其中一段由莉莉絲的研究接收器截獲；她讀到十三份完整血統因子培育紀錄後，才確認複製人軍團並啟動研究所。正式遊戲地圖會開放上方七個、下方七個外圍位置；十四個位置中一格仍由本局拉夫德魯占用，其餘十三格依序命名為「無風帶孤島 01～13」。

- 每個主島群外緣節點都會向正上方或正下方接出外圍航線；四個四皇據點也會因此繼續向外延伸。
- 十三條新外向航線與上下兩排十二條相鄰航線都屬正式可移動 route；每段固定有五個可停留海格。拉夫德魯原本的外向航線保留。
- 新世界航線在首次顯現時保留專用亮起動畫；動畫後的 125 個海格沿用一般海格的 16×16 尺寸、1px 邊框、圓角、藍色漸層與陰影，航線底線也沿用一般 10px 淡藍樣式，不使用永久放大、黃綠粗線或另一套青綠金邊樣式。未知孤島不額外疊加金色環形描邊／光暈。事件池、座標、島圖與航線資料不受視覺統一影響。

- 研究所主介面依素材固定為三個主入口：「免費醫療」、「血統研究」、「角色管理」；血統研究內含「科研補給／複製人培育」，角色管理內含「登船名單／研究收藏」。「複製人培育」使用 1:1 正式培育艙圖，玩家先選一份完整血統因子；演出到泡泡破裂節點才正式消耗該因子並建立一次 Lv.1、基礎型態的永久角色，演出未完成或重複提交不會預先消耗或多生角色。
- 每一張玩家角色卡都具有永久 `instanceId`。角色送入收藏時移動同一個角色實例，不重建角色模板；重新登船後保留等級、招式、修行、被動記憶、進化型態、攜帶物與外觀框。
- 研究收藏中的角色不參與戰鬥、主動換人或瀕死替補，也不能透過玩家交易移轉。既有交易仍只處理正式可交易物品。
- `player.researchLab` 使用 schema 5 保存收藏、下一個角色實例序號、下一個完整因子序號、`completeFactors`、個人研究點數、只升不降的研究等級與首次補發標記；舊 schema 1～4 存檔會依現有點數推導等級並安全補齊。已有船員與收藏角色固定取得「均衡型」血統傾向，六項能力各 `+1%`，不會隨讀檔重抽。
- 新培育角色只在永久實例建立時抽一次血統傾向：HP、攻擊、防禦、戰術、意志、速度中，一項 `+5%`、另一項 `+2%`、一項 `-2%`、其餘三項 `0%`。傾向參與正式能力計算，存入、取出、升級、進化、修行、讀檔及同步都不重抽；完整數值只在研究所角色詳情顯示。
- 培育完成、登船名單、研究收藏、角色詳情與同名比較的角色類型只顯示四職能：內部 `戰鬥型／偵查型／移動型／輔助型` 對玩家顯示為「攻擊型／偵查型／速度型／輔助型」。均衡、堅韌、強攻等血統傾向名稱不是角色職能，不再作為培育角色的主類型顯示；其永久百分比效果只標示為「個體能力修正」。
- 同一角色模板可由重複因子生成多個永久實例並放入研究收藏，但船上六人中同一 `card.id` 最多一名。新角色預設進收藏；船上未滿六人且無同模板時可立即安排登船。收藏容量不設玩家可見上限，每頁六名，可依取得順序、名稱或等級排序，並可篩選及比較同名個體。
- 正式戰後抽取目前共有 66 種敵人／Boss 來源身份。青雉、巴其、克洛克達爾、Mr.1、Mr.2、Mr.3 的因子優先沿用既有玩家模板；其餘來源使用 `lineage_*` 血統培育模板，覺醒路基來源依既有規則共用基礎路基模板。每一個來源身份仍各自保存暴擊 profile。這些模板只供研究所培育，不會加入開局選角、一般酒館或競技場對手池。
- 獨立敵人模板不直接複製敵人當場的等級、HP 包絡、Boss 倍率或全域敵方傷害倍率。敵人 profile 本身不新增船員職能；只有完整因子在研究所培育成永久玩家卡後，該卡才固定取得戰鬥型、偵查型、移動型或輔助型之一，並使用該職能的玩家版 Lv.1 基礎能力、個人移動值與被動記憶能力加值。分類不按角色屬性或人數平均：以直接輸出／正面決戰為主者歸戰鬥，只有明確感知／情報能力者歸偵查，以高速位移／運輸為主者歸移動，以控制／弱化／防禦／指揮／召喚為主者歸輔助。45 種獨立模板因此分配為戰鬥型 25、偵查型 1、移動型 8、輔助型 11；青雉等 6 種既有玩家模板保留原本正式職能與被動，51 名合計為戰鬥型 28、偵查型 2、移動型 9、輔助型 12。獨立模板不建立原資料不存在的角色專屬被動，`passive` 保持「無」。四皇、伊姆與神之騎士團的階段戰專用 `yonkoMove`、`finalGateMove` 及第二階段狀態不會進入玩家卡；沒有獨立進化資料的角色維持基礎型態。
- 所有血統培育角色完成培育時固定已有 4 招可用，之後仍像一般船員一樣隨升級領悟新招。59 種獨立 `lineage_*` 玩家模板各有 8 招：前四招 Lv.1 解鎖，後四招依 Lv.15、25、35、45 解鎖；6 種沿用既有玩家模板者保留其正式進化與學招表，但同樣必須四招起手且至少有一招後續可學。升級共用正式 `gainCardExp()` 與四招替換佇列；舊培育角色會自動補滿四個 Lv.1 招式，已達解鎖等級的後期招式則補入待學習佇列，不需重新培育。
- 十三座 Boss 培育角色的傷害招式不再沿用普通 T1 的 `55／70／88／110` 威力曲線，而依角色實際傷害招數量套用 `65／82／102／128`；傷害招少於四招時會拉開索引，確保最後一個傷害招仍達 128。洛克斯使用 `70／90／115／140`，普通血統角色的原階級曲線不變。這些是玩家版威力，不直接複製敵方 Boss 的 200 以上技能威力。
- 舊完整因子可用正式敵人 key 或唯一精確姓名解析，`rob_lucci` 會相容到路基模板；仍無法辨識的未知因子會保留並顯示尚未建立模板，不會被消耗。敵人模板角色沿用正式敵人角色圖，登船後可正常升級／學招、修行、使用四職能被動記憶、裝備攜帶物、戰鬥換人、存入收藏及讀檔。隊伍四職能效果每次都由目前實際 `player.crew` 重新計算：培育角色安排登船後立即納入其職能人數，送回收藏或下船後立即扣除；研究收藏、未登船角色及敵人 profile 一律不計，競技場則只計入入選的兩名。
- 完整因子解析依因子階級固定取得研究點數：ED 10、CB 20、A 30、S 40、SS 70、SSS 120。解析前必須二次確認；成功後不可復原、不可再培育或突破，也不能透過反覆融合無限堆疊角色能力。
- 培育角色的真實血統成長階段保存在同一角色實例的 `lineageGrowthStage`。研究所詳情顯示 S／SS／SSS；研究所以外仍使用角色既有 tier 顯示，不把血統階段混入一般招募或戰鬥階級。
- S→SS 必須同時滿足 Lv.99、使用該角色資料中最高階進化型態（沒有進化資料者以基礎型態完成）、被動記憶 Lv.3、六項修行點數總和至少 90，並消耗同角色完整因子 1、20,000 B 與 200 研究點數。完成後六項基礎能力各在 S 基礎上乘以 1.08。
- SS→SSS 必須已是 SS、Lv.99、最高型態、被動記憶 Lv.3、六項修行各 30 點，且玩家至少擊敗洛克斯一次；消耗同角色完整因子 2、完美血統核心 1、50,000 B 與 500 研究點數。完成後六項基礎能力再以 SS 基礎乘以 1.08；SSS 是固定最高階，不能重複突破。
- 血統階段倍率套在等級與正式進化能力之後、永久血統傾向與修行／記憶平加值之前。突破移動同一 `instanceId`，不降低或清除等級、EXP、六項修行、招式與 PP、被動記憶、進化與解鎖型態、血統傾向、外觀框、攜帶物、培育來源或取得時間。
- `完美血統核心` 是不可交易的重要道具，正式 1:1 圖示會在 SSS 突破需求與重要道具背包以同一固定比例顯示；擊敗移動蛋頭島的洛克斯後，每位實際參戰者各取得 1 個。
- 研究所狀態、完整因子、永久角色、真實血統階段、完美血統核心與七種抽取器持有量直接包含在手動存檔與 `BOARD_GAME_STATE` 完整快照。操作方可醫療、採買／製作、培育、解析、突破、存入與取回；觀看方顯示相同需求與結果的唯讀畫面。CPU 會先完成當下可成立的突破，沒有可突破角色時才自動培育一份相容因子，符合六人與同名限制時安排登船，再依既有規則醫療與補給。

### 拉夫德魯後：競技場島

- `postgameWorld.researchLabsActive` 開啟後，原始島種為 `tavern` 的正式酒館在地圖及落點流程中顯示並運作為競技場；島 id、座標及航線不變。敵人島暫時轉成的酒館仍是純酒館，不會被轉成競技場。
- 競技場對手池使用目前 51 名正式我方角色模板。每名對手都是完成體：固定 Lv.99、六項修行各 30／30、戰鬥記憶 Lv.3、血統突破 SSS，並使用該角色正式資料中的最高進化／覺醒型態；對手是獨立戰鬥快照，不會修改玩家自己的同名永久角色。
- 玩家從目前上船船員中選擇剛好兩名出戰，對抗一名指定對手；正式 battle view、主動換人、戰鬥道具目標與瀕死替補都只會列出這兩名，未入選船員不能用換人／替補指令繞過限制。CPU 會自動選擇一名對手與前兩名船員。
- 每次進場時保存玩家全隊入場前的 HP、PP、能力階段、異常狀態與上場索引，所選兩名改以滿 HP、滿 PP、無能力升降及無異常狀態開始。勝利、戰敗或逃跑後回復入場前快照；道具若在戰鬥中消耗仍照正式規則扣除，戰敗不送往推進城。
- 多人局若一個戰鬥回合後暫停，競技場 battle 與入場前回復快照保存為該玩家的 `pendingBattle`；下一次輪到該玩家時可在原島續戰，直到正式勝負或逃跑才回復場外狀態。
- 勝利依對手基礎 `tier` 給個人研究點數：T1 為 25 點、T2／T3 為 15 點、T4／T5／T6 為 10 點。競技場不發普通貝里、懸賞金或 EXP；同一對手可重複挑戰。
- 競技場選擇畫面使用專用 1672×941 主框，顯示 51 名可捲動對手、六格船員及兩個操作按鈕；觀看方收到既有 `spectator-modal` 唯讀內容。研究點數與 battle snapshot 隨手動存檔及既有 `BOARD_GAME_STATE` 完整快照同步。
- 競技場勝利已接入共用戰後抽取流程，對手以 SSS 抽取階級提供一次抽取機會；抽取成功先取得帶有原始玩家模板 id 的完整血統因子。競技場完成體的等級、修行、記憶、突破與進化不會複製，帶回研究所培育後固定生成 Lv.1、六項修行 0、戰鬥記憶 0、S 階、基礎未進化型態的永久角色。

### 拉夫德魯後：正式戰後血統因子抽取

- `postgameWorld.researchLabsActive` 開啟後，新發生的正式勝利會在原 `board_battle.html` 敵人退場前建立一次抽取機會；解鎖前的勝利不顯示，也不追溯舊討伐紀錄。戰敗、逃跑及黑轉支配的我方前哨戰不提供抽取。
- 敵人 HP 歸零後先保留原本戰鬥背景、我方／敵方 HUD、雙方角色卡與敵人外觀框，以下方圖片式雙面板顯示戰鬥紀錄和「進行提取／不要提取」。只有選擇進行後才切換研究艙抽取背景；沒有任何抽取器時仍必須顯示「沒有可用的血統因子抽取器」圖片式結果，玩家確認後才回原戰鬥結算，不能靜默跳過整段流程。
- 進行提取後使用 `board_lineage_extraction_battle_demo.html` 定案的巨大七連彈巢：完整正圓放大至舞台高度約 130%、圓心移到畫面左外側，只露舞台內半圓；目前孔位由發射底框左圓顯示。玩家可用滾輪、方向鍵或上下拖曳旋轉，確認孔位後才消耗所選抽取器 1 個。
- 確認開始後不論成功、失敗、重整或同步重送都不退還抽取器；同一 `attemptId` 重複開始或完成不會再次扣除或發放。放棄時不消耗。
- 第一階段依 ED／CB／A／S 產生 8／9／10／12 個 OSU 式縮圈目標，累積 3 次 Miss 會提早結束該階段；SS／SSS 仍保留原抽取階級、基礎成功率與上限，但三階段操作難度封頂為 S，同樣使用 12 個目標、900ms 單點時間、S 級目標大小與 Perfect／Good 容錯、2300ms 鎖針及 2400ms 雙環週期。三段各結算一次 Perfect／Good／Miss，分別加 7／3／0%，總加成最高 21%。
- 正式抽取沿用戰鬥頁既有 `#enemyCard` 與外觀框，進入彈巢後隱藏雙方 HUD 與我方卡但取消敵人 HP 歸零的淡出動畫，使敵人卡在三階段與演出中保持可見。彈巢孔位與確認圓槽不額外生成圓形光暈；第一階段目標限制在敵人圖安全區，狀態列顯示目標／COMBO／MISS；第二、三階段都要由玩家按下開始後才運作，鎖針／雙環依示範頁比例滿框並持續循環到玩家點擊，不因完成一圈自動判 Miss。判定只在敵人框中央顯示 `PERFECT／GOOD／MISS`。三段完成後播放約八秒的抽取器旋轉鎖定、框內／框外光束、敵人圖上的三次封存呼吸脈衝與成功回收或失敗掙脫；光束、命中環與封存指示都依所選抽取器色系顯示，框外光束必須位於敵人角色卡上方。成功或失敗判定完成後會出現對應的「查看提取結果」按鈕，未點擊時仍於八秒後自動前進；結果頁固定提供「繼續戰鬥結算」，按下後必須切回原戰鬥結果／獎勵面板，再由原「返回地圖」完成戰鬥，不允許只關閉抽取層或因演出結束而無操作入口。手機與平板只等比縮放 1024×576 舞台，不改變判定或正式結果。
- V199 起只要正式 `lineageExtraction.scopeKey` 開啟，戰鬥頁必須先停止敵方擊倒退場計時器、清除擊倒隱藏標記與 `portrait-ko`／受擊 class，將原敵方卡恢復為正常圖後再刷新抽取控制器。伽治的複製兵護衛層同時清空並隱藏；後續較慢的舊 KO callback 也不得再次把敵卡淡出。這是共用顯示修正，不改抽取資格、成功率、扣除或發放權威。
- V200 起按下「進行提取」進入七連彈巢／三階段操作後，原敵方卡的操作模式層級固定高於研究艙全螢幕背景；敵方卡與外觀框必須在右側實際可見，不可只存在 DOM 或圖片已載入卻被背景遮住。此層級只作用於抽取操作模式，不改詢問／結果面板與抽取權威。
- V202 起三階段完成後，由抽取器射向敵方卡的終局採樣光束固定顯示在研究艙與敵方人物卡上方；這只修正演出層級，不改三階段成績、成功率、抽取器消耗、完整因子發放或多人同步結果。
- 結果頁的「繼續戰鬥結算」必須完整落在右下圖片框內，不得因固定面板高度或 `overflow:hidden` 被裁切；成功與失敗使用同一個續行入口，之後都回到原戰鬥獎勵及「返回地圖」。
- 敵人基礎成功率／上限依序為 ED 55／95%、CB 40／95%、A 28／95%、S 18／90%、SS 10／85%、SSS 5／75%；再加入所選抽取器加成與三段操作加成，不提供保底。
- 正式版與 `board_lineage_extraction_battle_demo.html` 的判定輸入統一在按下滑鼠／觸控的 `pointerdown` 當下取樣；第一階段保留 30ms 結束緩衝、目標間隔 190ms，三階段轉場依示範頁使用 920／900ms，避免正式版因 `click` 放開才判定而比示範頁更嚴格。
- 成功只在該玩家的 `researchLab.completeFactors` 新增一份完整血統因子，保留敵人 key、名稱、階級、來源戰鬥、抽取器與正式判定資料；不直接新增角色，也不允許一般交易。失敗不新增因子。
- 共鬥的每位實際參戰者各自使用自己的抽取器並各自結算，所有人完成、放棄或無抽取器後才開放原戰鬥結算；觀看方不能操作。CPU 會自動選擇可用加成較佳的抽取器並完成三段模擬，不會卡住結算。
- 原貝里、懸賞、EXP、道具、研究點與島嶼勝利流程仍由 `board_game.js` 的原戰鬥結算處理。完整抽取狀態與因子資料沿用手動存檔及既有 `BOARD_GAME_STATE` 完整快照，沒有新增 localStorage key 或 Socket.IO event。

## 水之七島船隻改造

目前船隻相關規則橫跨：

- 玩家 ship 狀態。
- `board_items.js` 的船隻道具、裝備、材料。
- `board_game.js` 的船隻加成、移動或戰鬥套用。
- `board_water_seven.html` 的船隻改造 UI。

任何船隻改造都要確認：

- 材料是否存在於 `GAME_ITEMS`。
- 商店或掉落是否能取得材料。
- 船隻加成是否會在移動 / 戰鬥 / 存檔後維持。
- 線上同步是否會包含新欄位。

## 多人規則限制

Board 多人模式不是 server authoritative。實際規則在前端執行，server 只接收快照。
因此新增或修改任何會改變 `gameState` 的規則時，都要確認：

- 本機玩家是否有權送出這次狀態。
- 其他 client 收到快照後能正常 `loadManualGame()`。
- 舊存檔是否能由 `normalizeLoadedGameState()` 補齊欄位。
- 戰鬥、副本、交易、合作戰是否會因不同 client 時序而重複結算。

### 魔人歐斯鹽袋賭局與巨型鹽彈

- 十三 Boss 第 12 位是魔人歐斯；約克第 12 張線索也指向歐斯。舊存檔中的第 12 位洛基島／線索／進行中戰鬥會遷移成歐斯，但不移除玩家既有 Ragnir。
- 歐斯固定最大 HP 55,555，不受一般 Boss 平衡器縮放；速度固定 18，四招本身命中率為 48%／42%／38%／32%，且先天閃避能力使我方命中率額外提高 16 個百分點。這些都是歐斯自身基礎能力，不會在狀態列出現命中、速度或閃避 -3；其直接攻擊基礎威力仍高，也可用普通傷害慢慢擊倒。

- 專屬掉落「魔人歐斯的巨人腰帶」：最大 HP ×1.5、直接攻擊傷害 +20%、速度 ×0.7，Boss 勝利固定 10% 掉落率。

### Tot Musica 雙世界同步攻擊演出

- 單人開戰先在中央六個空白順位格編排左隊與右隊，各隊三格、第一格為先發、第二與第三格為替補；必須把下方六名船員拖入所有格子，觸控裝置可先點船員再點順位格。全部排完才可確認；編隊與玩家選招時都不顯示 Tot Musica，整場維持同一個左右對半專用舞台，不會返回一般單人戰鬥畫面。

### 拉夫德魯結局後的新世界交棒

- 第一次完成最終之島結局時，無風帶消失、十三座孤島與新航線、移動蛋頭島及研究所啟動仍一次寫入全房共用世界狀態。
- 後續五幕人物對話播放期間保持 `resolutionLock`。目前回合控制者看完最後一句或按「跳過」後，才展開新世界地圖並結束本回合；不再由固定秒數在玩家尚未看完時強制交棒。
- 舊存檔若世界與研究所已解鎖但缺少後續劇情，只補播同一段對話；補播完成不再消耗或結束當前回合。

### 共鬥後臨時功能島的 CPU 決策

- 普通敵人島被共鬥擊敗並暫時轉為商店、醫院或酒館後，仍留在島上的其他參戰者在自己的下次回合選擇「進島」或「擲骰出發」。
- CPU 會依當下狀況判斷：隊伍需要恢復才進醫院、隊伍未滿且資金足夠才進酒館、有實際可購買補給才進商店；其餘情況直接擲骰，不等待真人替它操作。
- 此選擇只控制共鬥後的臨時服務，不改變臨時島期限、戰鬥獎勵、回合順序或共鬥參戰資格。

### 戰鬥開場完成與恢復

- 開場對話播放期間仍不能選招；完整播完後才開始既有開場被動與第一回合操作。
- 同一段對話若因 iframe 重載或同步時序遺失完成回報，戰鬥頁會重新送出完成確認；若確認持續未抵達，主頁只解除這一段開場對話鎖，不能解除攻擊動畫、替補、Boss 機制、血統抽取或結算鎖。
- 共鬥只允許目前取得 battle 操作權的玩家完成此確認，觀看其他玩家戰鬥不會取得選招權。

### 多裝置開局與控制權

- 房主開始遊戲後，由房主建立唯一的初始遊戲狀態；其他電腦、平板或手機會等待並自動同步同一局，不會以自己的隨機地圖覆蓋房間。
- 換頁造成的短暫離線不會立即更換房主；超過 8 秒且原房主仍未回來，才由在線真人接手初始同步。
- 每個裝置只操作與自己 `userId`／`clientId` 相符的玩家。不是自己的選角或回合時只能觀看，不能代替該玩家按指令。

### 玩家停靠交易

- 玩家交易必須在海上航線的同一個海格進行，島嶼、CPU 或戰鬥中的玩家不能參與。
- 只有骰數全部走完、船停在另一名可交易真人所在海格時，後抵達者才會收到交易提示。
- 移動途中只是經過其他玩家的海格時直接繼續航行，不停船、不詢問交易，也不扣除額外步數。

### 戰鬥角色圖與特殊機制作用域

- 力／速／技屬性維持顯示在戰鬥左上／右上 HUD 資訊列，不在角色戰鬥圖上方另外顯示屬性橫條。
- Boss 專用視覺與操作只在對應的 `postgameBossMechanic.key` 戰鬥中生效；例如泰佐洛的金流河只在泰佐洛戰鬥的第一／Golden Tesoro 階段依淹沒段數顯示，其他一般戰鬥與特殊 Boss 不共用該覆蓋層。
- 泰佐洛全新挑戰固定以 3000／3000 HP 進場，開場防禦與特防各 +2；同一場 `pendingBattle` 的待續戰鬥保留當時 HP，不會重新補滿。HP 首次降到 50% 以下才進入 Golden Tesoro。
- 泰佐洛金流河使用透明液態黃金正式圖片，固定在玩家角色圖框內由下往上顯示 1／3、2／3、3／3；它不依角色身材、臉部或半身位置對位，也不跟著角色的攻擊前衝或受擊震動離開圖框。
- 泰佐洛變身前後都只有敵方成功命中的非增益／治療招式會替結算後仍存活的目標增加金流，每次固定一段；玩家攻擊不會降低金流。第三段全滿時沿用一般純文字替補清單在當回合選擇新角色，不顯示泰佐洛專用圖片卡；換下去的角色立即歸零，新角色到下回合才可行動。若第三擊同時使 HP 歸零，金流停在原段數並改走一般倒下／替補流程。Golden Tesoro 額外固定只承受原傷害的 40%。
- 專用戰鬥頁效果不得改動一般戰鬥的傷害、招式、回合順序、CPU 行為或角色圖渲染規則。

### 二周目同格玩家切磋 PK

- 準備畫面同時公開雙方船上的六名角色；任一角色都能開啟詳情，但不得顯示或由 DOM 輸出攜帶物名稱、圖像、欄位或效果。

- 只有完成一周目、同時位於同一個海上航線格的兩名真人玩家能切磋；由目前地圖回合玩家從船長指令或同格停靠提示發出邀請，對方同意後才進入準備室。CPU、島嶼位置、任一方不足三名船員或已在其他流程中時不能開始。
- 正式 PK 使用獨立的雙方對稱戰鬥快照。選中的三人以滿 HP、滿 PP、零能力階級與零異常狀態進場；主線船員 HP、PP、目前出戰位置與攜帶物實體都不會被改寫，勝敗不發放貝里／經驗，也不觸發瀕死、推進城或海軍本部。
- PK 不會連續佔住地圖回合。每逢輪到其中一名參戰玩家，該名玩家先秘密選招、另一名參戰者再回應；兩邊都完成後才依行動優先度與有效速度結算一個 PK 輪次，接著立刻照原本玩家順序換下一位。例：原順序 A→B→C→D，A 挑戰 C 時為「A 選、C 選、結算、換 B」；B 完整進行普通回合後輪到 C，則為「C 選、A 選、結算、換 D」。B、D 不會被切磋鎖住，也不會失去自己的普通回合。
- 雙方都可使用原有招式、換人與倒下後替補流程；三名角色全倒下才分出勝負。尚未分勝負時，PK 的 HP、PP、狀態與替補結果暫存在 `activeSpar.battleSnapshot`，非參戰者回合不建立全域 `battleState`；輪到下一名參戰者才恢復戰況。
- 準備室與對手戰鬥 HUD 都不公開對方攜帶物，但正式結算會對稱套用雙方裝備者與承傷者的攜帶物效果；自己的攜帶物仍可在自己的戰鬥 HUD 查看。
- 多人房使用既有 `BOARD_GAME_STATE` 完整快照同步；兩名參戰玩家都能提交 `spar-*`／PK 戰鬥更新，非參戰玩家不能改寫該場狀態。沒有新增 Socket.IO event 或 localStorage key。手動主線存檔會排除進行中的切磋快照。
- 準備室角色卡以框色呈現陣營，力／速／技直接置入卡框左上盾牌孔，不另設屬性徽章或情報按鈕；右上數字只在選入後顯示出戰順位。點擊對方整張角色圖即可開啟詳情；己方尚未鎖定時點卡仍用於選人，鎖定後再點才查看詳情。鎖定／揭曉只改光效與明暗，不額外公開角色的攜帶物。
- 角色卡的海賊框必須是位於人物圖上方的鏤空覆蓋層；人物窗不可使用不透明深色卡底，也不可把角色縮在框後。姓名與階級資訊區可保留實底以維持可讀性，角色原圖本身不得被覆寫或加工。
- 小卡必須保持鏤空框原生 3:4 比例，不得因左右名單 grid 改變而拉伸。角色名稱只能置於框圖下方姓名木牌中央；階級、定位與等級只能置於再下一層資訊槽，入選狀態以發光與順位徽章呈現，不另加文字覆蓋姓名。
- 角色詳情也必須使用位於內容上方的 3:2 RGBA 鏤空覆蓋框：左側人物窗、右側名稱、六項能力與招式資訊孔皆為真透明，角色圖與 HTML 資料分別置於框後／框內，不得把不透明整張底圖當作資訊框。
- 小卡與詳情內容必須依素材實際 Alpha 開孔中心對位：小卡人物、盾牌屬性、順位、姓名與三欄資料皆置中；詳情人物、屬性盾牌、姓名、標題、六個能力欄、招式資訊區及返回文字也各自置於對應框孔中心，不得只用目測偏移。
- 詳情頁力／速／技以左上實體盾面的視覺中心對位，而不是透明人物窗中心；單字需使用固定行高與可辨識的大字級，並保持在盾牌金框內。
- 角色圖只可顯示在鏤空框的實際人物內孔，左右不得穿出金屬直條，上方不得蓋住橫樑，下方不得進入姓名木牌；帽子、角、頭髮與肩部都受同一裁切窗限制。
