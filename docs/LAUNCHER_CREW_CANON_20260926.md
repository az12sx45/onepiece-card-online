# 草帽房間對話設定與驗證 — 2026-09-26

範圍：啟動器 1.1.13 的 `desktop/launcher-room-dialogue.js`、`scripts/launcher_room_dialogue_qa.js`。本文件紀錄內容研究、原創日常場景、資料契約與實際執行的資料驗證；不代表動畫、美術、正式部署或真人使用驗收已完成。

## 改寫原則

- 十名角色、45 個雙人組合都有獨立場景；每組 3 場、每場 4 回合，共 135 場、540 句。每一場保留起頭、接話、回應和收尾，不能把相遇順序直接當成台詞順序。
- 另有 200 句點擊／工作／親密互動／休息／完成領取台詞（含每人 2 句、共 20 句 `claim`）、38 句角色專屬家具台詞。所有文字為本專案新寫的短句，並非漫畫或動畫逐字引用。
- 角色關係要影響回話：索隆與香吉士嘴硬而合作、騙人布逞強而喬巴相信、娜美給指示而甚平落實、魯夫直接信任專業、羅賓接住好奇也保留冷幽默。
- 船員不被縮成單一笑點：不每句肉、錢、迷路；喬巴有醫師的堅持、騙人布有真手藝、香吉士照顧所有夥伴、佛朗基有感性、布魯克能安靜真誠、甚平也會笑。
- 主編逐句抽查後，補回少量可辨識的說話習慣：喬巴受誇獎時嘴硬卻藏不住笑、布魯克的笑聲、索隆對香吉士的「圈圈眉」稱呼，以及羅賓平靜的黑色幽默。保留這些特徵而不讓每一句都重複同一笑點。
- 表演資訊同時提供說話者與聆聽者。155 回合安排點頭、驚訝、抗議、微笑等非預設反應，其餘採專心聆聽。表演 token 是語義意圖，不能拿文字標籤代替角色美術表情。

## 時期與造型界線

房間允許玩家擺放不同時期服裝，是收藏房間的集合場景，沒有宣稱這十套服裝曾在正史同一天共處。對話只用船上日常與長期性格，避免明示懸賞金、最新身份、眼傷、武器更換、特定戰役結局、後期能力或私人重大過去。白衣索隆與兩年前造型不應因現在的角色頁而被補上左眼傷疤；造型須由美術規格另外核對。

不把香吉士與娜美／羅賓寫成已確認戀情，不把索隆與香吉士寫成真心仇敵，也不讓魯夫、喬巴忽然拆穿騙人布在原作中的全部祕密。`PROFILES.closeTo` 是本房間的互動導向標籤，不是原作親密度排名。

## 程式契約

`OnePieceRoomDialogue` 同時支援瀏覽器全域與 CommonJS。原先的 `pair`、`greeting`、`interaction`、`activity`、`CHARACTER_LINES`、`CHAT_MOODS`、`PAIR_LINES` 入口保留。

### 完整對話

```js
const scene = OnePieceRoomDialogue.scene('sanji', 'zoro', cursor, {
  furnitureKey: 'swords-rack', // 選填；有符合標籤的原創場景時優先
  recentSceneIds: ['zoro-sanji-1'] // 選填；避免最近重複
});
// {
//   id, pair: ['zoro', 'sanji'], topic, relationship, tags, cooldownMs: 90000,
//   turns: [{ speaker, line, mood, pose, action,
//             listener: { key, mood, pose, action }, durationMs }, ...]
// }
```

- 相遇參數可以反向，但不反轉劇情。上例仍按回傳的 `speaker` 播放「索隆 → 香吉士 → 索隆 → 香吉士」，不能因角色容器順序而先播答案。
- 每一回合先結束上一回合氣泡，說話者採自己的 pose/action，另一位採該回合 `listener`，雙方持續面向彼此。最後留收尾時間才恢復閒逛。
- `durationMs` 按句長落在 2300–5000 ms，room 引擎可在可讀範圍調整。每組有 90 秒重播冷卻的建議值，實際排程由 room 引擎保存。
- 情境場景最近都播過時，先擴大到該組未播過的場景；該組全部播過才循環。沒有這對角色就回傳 `null`，不生成套版內容。
- `scene()` 回傳副本；外部修改不會污染原始劇本。資料匯出值遞迴凍結。

```js
activity('chopper', 'medicine-cabinet', 1);
// { speaker, line, mood, pose, action, verb, furnitureKey }
```

`interactionBeat` 類型：`chat`／`work`／`bond`／`rest`／`claim`。工作台詞用於既有 server 授權後的視覺回應，本資料不改金幣計算、工作時長、領取限額或交易邏輯。`bond` 表達熟悉與關心，不在文字中虛構親密度已增加；以 server 回傳為準。2026-09-27 新增 `claim`：只有成功領取工作報酬後播放，使用完成／交付語氣，不能回播開始工作的指令；每位角色有 2 句不同的完成台詞與對應 mood/pose/action。

`activity` 只回傳該角色已寫的家具活動，未知家具回傳 `null`。避免魯夫突然像專業廚師、索隆突然替人讀航線；主程式若需要其他活動，應使用合理的通用等待或另寫專屬內容。

舊 `pair(a,b,index)` 仍回傳 `[[a 的第一句, mood],[b 的第一句, mood]]`，僅供舊版相容。新版 room 應用 `scene` 播放四回合，不能以舊入口宣稱已完成新互動。

### 表情和動作意圖

`mood` 兼容現有四種分類：`happy`、`surprised`、`focused`、`annoyed`。可用 `pose`：`idle`、`talk_happy`、`talk_annoyed`、`surprised`、`focused_use`、`sit`、`wave`。新方向圖有 `listen` 時，room 可把 `action: listen` 升級到該影格，舊圖以 `idle` 相容。

| action | 中文意圖 | 表演重點 |
| --- | --- | --- |
| talk | 交談 | 自然說話，不全程誇張招手 |
| explain | 說明 | 專注指示，對方看向說話者 |
| nod | 點頭 | 簡短確認，不誤當成另一段演說 |
| laugh | 開懷 | 放鬆的笑與身體反應 |
| tease | 打趣 | 語氣輕鬆，保留對方接梗時間 |
| protest | 抗議 | 不滿、吐槽，非每次都暴怒 |
| reassure | 安慰 | 放緩、給對方放心的回應 |
| admire | 驚喜 | 眼神與身體表現興奮 |
| think | 思考 | 觀察、停頓，不能像在生氣 |
| bow | 致意 | 禮貌道謝或應允 |
| listen | 聆聽 | 收起說話姿勢、注視對方 |
| startled | 吃驚 | 被突然的事情驚到，與高興有別 |
| offer | 招呼 | 邀請、遞出幫助、讓出位置 |
| work | 專心 | 活動對準家具或手上工作 |
| rest | 休息 | 鬆開緊張，座姿需符合實際位置 |

`ACTION_LABELS` 提供中文標籤。這些語義不代表已生成 15 套獨立動畫；新版美術／room 必須實際表現，不能只在氣泡顯示動作字樣就算完成。
