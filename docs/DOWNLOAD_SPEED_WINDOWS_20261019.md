# Windows 遊戲下載排程改善（2026-10-19）

## 問題與範圍

玩家回報啟動器內下載遊戲約 300 KB/s。正式 1.2.23 `desktop/asset-store.js` 沒有固定下載速限；舊流程一次最多下載 4 個一般檔案，全部完成後才下載 32 MiB 以上檔案。公開 Board 清單有 6,261 個不重複 blob，2,681 個小於 64 KiB、4,911 個小於 256 KiB。大量小檔案容易受逐請求延遲與檔案作業時間影響。

本次只修改下載排程。`downloadBlob` 的 HTTP、R2 優先／來源備援、續傳、重試、SHA-256、大小核對、fsync、安全路徑與快取格式均保留。未改遊戲規則、存檔、帳號或同步。

## 排程與停止保證

- 全部待下載檔案共用 12 個權重名額，沒有原先的大小檔案分階段等待。
- 小檔案 `<=256 KiB` 使用 1 個名額，最多 12 個同時執行。
- 中檔案 `>256 KiB && <=8 MiB` 使用 3 個名額，最多 4 個同時執行。
- 大檔案 `>8 MiB` 使用 6 個名額，最多 2 個同時執行。
- 先選清單中目前名額足夠的檔案；等待名額的大檔案不占用空白工作執行緒。
- 第一個失敗會中止同批下載，保留原始失敗原因；所有進行中的工作停止後才回傳。取消同樣等待既有工作結束，避免舊下載持續寫入而與重試衝突。

## 真實 Electron 比較

測試使用正式原始 `AssetStore.downloadQueue` 與本次候選，透過 Electron 44.1.1 `session.fetch`，每次建立獨立且有擁有權標記的空白 QA 快取。計時包含安全路徑檢查、下載、寫入、fsync、重新讀檔 SHA-256、重新命名與指紋。未包含完整安裝的清單掃描／最後狀態整理及 UI IPC。

| 相同測試條件 | 舊版 | 候選 | 比值 |
|---|---:|---:|---:|
| 48 檔共 1,376,256 bytes，固定每請求 200 ms 延遲 | 4,340 ms | 1,854 ms | 2.34 倍 |
| 同一批 48 檔，固定每請求 50 ms 延遲、反向執行順序 | 1,353 ms | 753 ms | 1.80 倍 |
| 公開 CDN 同一批 24 檔共 276,733 bytes，暖快取 ABBA 各兩次合計 | 1,317 ms；420,247 B/s | 610 ms；907,321 B/s | 2.16 倍 |

公開比較先做一趟排除於比較外的暖機，再執行舊／新／新／舊；各次 24 個回應全部為 `cf-cache-status: HIT`，未將冷快取與暖快取差別算成程式改善。固定延遲的本機伺服器用於控制請求延遲，不能當成真實 CDN 冷快取數字。所有檔案均通過原下載器的大小／SHA 核對。

最初診斷另量到舊版同批 24 個小檔案全部 MISS 時僅 26,438 B/s；單一 3,929,145 bytes 的 HIT 檔案透過原下載器含檔案驗證為 3,696,279 B/s。因此不能認定存在固定 300 KB/s 速限。第一輪另一次 raw 暖快取比較逾時，失敗保留於原報告，沒有當成通過或用來計算改善。

測試電腦與路由的結果不等於朋友端或所有玩家的固定速度；冷 CDN、網路與儲存裝置仍影響實際時間。此文件記錄來源與 QA；公開安裝包發布由另外的發布證據確認。
